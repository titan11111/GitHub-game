## 個別評価

### Gemini — 教育者タイプ
**特徴**: ステップバイステップ。いきなり完成品を出さず、「まず土台、次は？」と選択肢を提示してから進む。
- 長所: 初心者への解説として最も丁寧。なぜそのコードなのかが分かる
- 短所: 「すぐに動くゲームを作って」という意図に応えていない
- 向いてる用途: 教育・学習補助

### Grok — バランス型
**特徴**: 完成品を一発出力。キーボード操作、Web Audio音響あり。フレームカウンタベース（frameTimer方式）。
- 長所: 音響実装が特徴的。Webゲームらしい雰囲気作りがうまい
- 短所: ボスなし、パワーアップなし。難易度調整が粗い
- 向いてる用途: プロトタイプ・デモ

### Claude Sonnet — 実装者タイプ（最高機能）
**特徴**: deltaTime方式（フレームレート非依存）、ボス・フェーズ制・パワーアップ・タッチ対応・HTMLオーバーレイUI
- 長所: ゲームとしての完成度が最高。マウス追従で操作感が独特
- 短所: コードが長く読みにくい。自動射撃のため「操作している感」が薄い
- 向いてる用途: 完成品デプロイ・モバイルゲーム

### ChatGPT — 実用的シンプリスト
**特徴**: 機能は最低限だが、コードが最もクリーンで読みやすい。上下左右移動可能（4方向）
- 長所: コードが分かりやすい。改造・学習しやすい構造
- 短所: エフェクト・音響・ボスなし。視覚的に地味
- 向いてる用途: ベースコードとしての改造・学習用ひな形

## 法人営業支援への応用視点（hojin-support転送）

この比較実験から以下が学べる：

1. **AIへの指示精度が出力品質を決める**
   - 「縦型シューティングを作って」という同じ指示でも出力が4倍異なる
   - → 営業提案でも「要件の明確化」が成果物の質を左右する

2. **各AIの「得意なこと」を知って使い分ける**
   - 教育→Gemini / 完成品→Grok・Sonnet / ベースコード→ChatGPT
   - → CopilotやAIツールも「何に向いているか」を理解して活用する説明材料になる

3. **マルチAIスタックの優位性**
   - 1つのAIで完結させるより、用途別に使い分ける方が品質が高い
   - → 法人向けDX提案で「AIを組み合わせる設計」を提案する切り口
