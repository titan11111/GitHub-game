## 1. 何を作り直したか（改修の理由）

前身は `gunkanjima-survival.html`（無線機パーツ5個収集→電波塔→60秒耐久）。
タイタン指摘：**「まだまだAI感が抜けない。もっとリアルを追求」**

### AI感の正体（コード上の実在箇所で特定した6点）

| # | 症状 | 旧コードの現物 | 対処 |
|---|---|---|---|
| 1 | 目標に光の柱が立つ | `beamMat`（加算合成の黄色い縦シリンダー） | **全廃**。探索は自分の目と地図で行う |
| 2 | 常時ナビ矢印＋距離m表示 | `#arrow` `#dist` `target()` | **全廃**。紙の地図＋方位磁針に置換 |
| 3 | 絵文字HUD／絵文字トースト | `❤️🍙💧⚡` `🥫 缶詰ゲット 🍙+35` | **絵文字ゼロ**。物の説明文に置換 |
| 4 | 勝利ジングル（ドミソド） | `[523,659,784,1047].forEach(tone)` | **全廃**。汽笛と波音のみ |
| 5 | 回転・浮遊し30秒で湧き直すアイテム | `it.m.rotation.y+=dt*2` / `respawnQ` | **静止・有限**。拾ったら無くなる |
| 6 | 危険が赤い輪で予告される | 落下瓦礫の `ringMat` | **音と粉塵で予告**。落下は建物際のみ |

### 加えて是正した技術違反

- 外部CDN依存（`cdnjs` の three.js）→ `three.min.js` をローカル同梱（監査の人間箱項目）
- `localStorage` キー無接頭辞（`gunkan_best`）→ `tg.259.*` 形式へ（鉄則・キー衝突対策）
- **ミュートが存在しなかった** → 設定パネルに実装（コントロールパネル方針の第1項）
- エントリが `gunkanjima-survival.html` → `index.html`（未公開のためリダイレクト不要。git履歴に旧名なし＝鉄則8の対象外）

## 2. 舞台の考証（どこまで実在に寄せ、どこを圧縮したか）

**誇張しないために、寄せた点と変えた点を両方書く。**

### 寄せた点（実在）

| 要素 | 実在の事実 | ゲーム内 |
|---|---|---|
| 島の形 | 南北約480m×東西約160m、6.3ha。護岸に囲まれた人工島 | 南北300m×東西100m（比率3:1を保持） |
| 30号棟 | 1916年築。日本最古の鉄筋コンクリート造集合住宅。7階 | 南西部・入れる（雨風をしのげる） |
| 65号棟 | 1945年着工。9階建てコの字型。島最大の鉱員社宅 | 北部・入れる。中庭あり |
| 70号棟（端島小中学校） | 7階建て。屋上にプール | 北東部・入れる |
| 端島神社 | 社殿は失われ、祠のみが岩山の上に残る | 中部の岩山頂。到達可 |
| 地獄段 | 65号棟から神社へ上る急階段の通称 | 岩山への唯一の上り口 |
| 総合事務所 | 南部。赤レンガ。共同浴場があった | 南部・入れる |
| 第二竪坑坑口桟橋跡 | 南部に残る桟橋の脚 | 南部の海側に脚のみ |
| ドルフィン桟橋 | 島の西側。現在も上陸はここから | 南西・ゴール地点 |
| 貯水槽 | 島内に真水はなく、対岸から送水していた | 高所に残骸。濁った残水あり |
| 上陸の可否 | **波高が基準（おおむね1.5m）を超えると上陸中止**。年間上陸率は3〜4割 | 波高が1.5mを割った朝にだけ船が入る＝ゲームの勝利条件 |
| 閉山 | 1974年1月15日に閉山、同年4月無人化 | 現在（無人・立入制限）設定 |

### 変えた点（ゲームのための圧縮・明記）

- 島を実寸の約6割に圧縮（480m→300m）。全長を走ると実測で約70秒かかる設計
- 建物の**位置関係**は実際の配置に寄せているが、**正確な測量図ではない**。棟数も12棟に絞った
- 内部構造（部屋割り・階段）は再現していない。「1階に入って風雨を避けられる」までを実装
- 時間を圧縮：台風の通過から夜明けまでを実時間 約7分で表現

### 前提（なぜ携帯で助けを呼べないのか）

夜半の時化で小型船が転覆、投げ出されて端島の護岸に打ち上げられる。
**携帯・財布ごと上着は海に持っていかれた**。島は無人で立入制限区域。
台風が抜けて波が落ちれば、朝の上陸ツアー船が南西のドルフィン桟橋に入る。
**それまで生きて、桟橋で自分の存在を知らせること。**

## 3. 生存モデル（4軸）

バーを4本並べるのではなく、**体の状態として言葉で出す**。数値は細い目盛りで副次表示。

| 軸 | 減る理由 | 回復手段 | 限界で何が起きるか |
|---|---|---|---|
| **水分** | 常時。走ると倍速 | 貯水槽の残水（濁り・3回分）／一斗缶に溜まった雨水（島に2個） | 尽きると体力が急落。濁り水は95秒間、水分の減りが1.6倍になる |
| **体温** | 濡れ＋風＋夜。台風中は屋外にいるだけで落ちる | 屋根の残る棟に入る（濡れも乾く）／桟橋の焚き火（点火後） | 低下で視界が狭まり、手がかじかんで走れなくなる |
| **体力** | 常時ゆっくり | 潮だまりの貝・海藻（干潮時のみ）／漂着した缶詰 | 尽きると体温維持ができなくなる |
| **出血** | 崩落の直撃・露出した鉄筋 | 布で止血（布は火種にも要るので取り合いになる） | 止めないまま放置すると死ぬ |

海水は飲めない（飲むと水分がさらに減る）。島に自生する食料はほぼない。

## 4. 目的と勝敗

### 勝利条件

1. 夜明け（開始から約5分30秒）まで生きる
2. **合図の火の材料をドルフィン桟橋に運ぶ**：流木×4／ライター／乾いた布
3. 波高が1.5mを割り、船影が現れたら火をつける

**火が焚けていないと、船は島影を通り過ぎる。** 生き延びただけでは助からない。

### 敗北条件

- 体力が尽きる（脱水・低体温・失血・崩落の直撃）

### 運搬の制約

流木は**一度に2本まで**しか持てない（かさばるため）。桟橋へは最低2往復が必要。
この往復の最中に台風のピークが来るよう、時間を設計している。

- 入力は **Pointer Events に統一**し、全ボタン・全スティックに `setPointerCapture` を入れる（押しっぱなしバグ対策）

### ポーズ（明示ポーズ）

Ⅱ ボタン／P／START でいつでも停止。停止中は時間・天候・体の状態がすべて止まる。
`visibilitychange` による自動停止も併設する。

## 6. 演出の原則（AI感を出さないための禁止事項）

実装中に迷ったら、ここへ戻る。

1. **目標を光らせない。** 柱・矢印・距離表示・ミニマップ上の点滅を作らない
2. **絵文字を使わない。** HUD・トースト・タイトル・ボタン、すべて文字と細線のみ
3. **音階を作らない。** 取得音・勝利音に長調のアルペジオを鳴らさない。鳴っていいのは環境音・物音・汽笛だけ
4. **物は浮かない、回らない、湧き直さない。** 地面に落ちている物を、しゃがんで拾う
5. **危険を図形で予告しない。** 予告は音と粉塵。落下は建物の壁際にだけ起きる
6. **色を鮮やかにしない。** 彩度を落とし、コンクリート・錆・海の3色系に寄せる
7. **説明を叫ばない。** 「！」を連ねない。取得時は物の説明を1行出すだけ（例：「一斗缶。底に雨水が溜まっている」）

## 7. 技術・制約

- three.js r128（`three.min.js` をローカル同梱。CDN参照なし）
- テクスチャはすべて Canvas で手続き生成（外部画像ゼロ）
- 音はすべて WebAudio の合成（外部音源ゼロ）。iOS の unlock は初回タップで `AC.resume()`
- フォルダ合計サイズ目標：**1MB未満**（20MB鉄則に対し十分な余裕）
- `devicePixelRatio` は 1.5 で上限。嵐の視程短縮を fog で行い、描画負荷を上げずに没入させる

## 8. 座標と方位（実装の約束ごと）

- `+x` が **北**、`+z` が **東**。島の長辺（300m）が南北、短辺（100m）が東西 ＝ 実際の端島と同じ向き
- ドルフィン桟橋は `x=-118, z=-56` ＝ 島の **南西**。船も南西の沖から現れる
- 画面上の方位帯（コンパス）はこの定義に合わせて `yaw` から −90° 補正している
- 紙の地図は横長の用紙に合わせて **右が北**。手描きの略図という設定なので方位記号で示す
