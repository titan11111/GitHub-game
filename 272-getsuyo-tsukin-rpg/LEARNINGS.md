### 何が無かったのか（実測）

着手時点のフォルダは3ファイル・12KB。`index.tsx` は **Cloudflare Workers + Hono + D1** のサーバーコードで、
HTML文字列の中から `/static/js/app.js` を読んでいたが、その実体は**リポジトリ全体をgrepしても存在しなかった**。
`~/Downloads` も空。つまり「ゲーム本体が最初から一度も存在していない」状態だった。

途中で `build-standalone.mjs` / `standalone-entry.js` / `template.html` が追加され、
**意図されたモジュール構成（config / utils / builders / world / interactions / game / minigames）が判明した**。
この import 文の一覧が実質の設計書になった。

### 学び1: 「参照されているのに無いファイル」は、名前と import 文が設計書になる

`standalone-entry.js` の import 一覧（どのモジュールから何をexportすべきか）と、
`index.tsx` の HTML（HUDのid・操作ヘルプの本文・エンディング5種の key）を突き合わせると、
**仕様を推測せずに復元できる範囲がかなり広い**。
エンディングの `missstop` `tetris` という key から「乗り過ごし」「筐体で時間を溶かす」という遊びが確定し、
`playCoffee` `playPigeons` という関数名から寄り道の中身が決まった。
→ 次回に使う条件: 器だけが残ったフォルダを復旧するとき、まず「存在しないファイルへの参照」を全部集めて設計書として読む。

### 学び2: 縦持ちの3Dは、カメラを「天井の下」と「部屋の中」の2つで縛らないと画が消える

3箇所で同じ事故を出した。

1. **天井の上に出た** — 電車（天井2.6）と会社5F（天井3.4）で、既定のカメラ高さ 4.4 が天井を越え、
   画面いっぱいに天井の上面が映った。エリアごとに `cam: {back, up}` を持たせて解決
2. **壁の外に出た** — 自宅（奥行11m）でカメラを下げたら、今度は背面の壁の外側に出た。
   壁は FrontSide なので外からは面が見えるだけで、視界が茶色一色になった。
   → `indoor: true` のエリアはカメラを `bound` の内側にクランプ
3. **横が見えない** — FOV 58° は縦持ち（aspect 0.46）だと**水平画角が実質29°**しかなく、
   部屋の左右にある家具が一切映らなかった。72° に上げて解決

→ 次回に使う条件: 屋内のある3Dを縦持ちで作るとき、(a) カメラ高 < 天井高 (b) カメラ位置を部屋の内側にクランプ
(c) FOVは70°前後から始める。この3つを**最初のコミットで**入れる。あとから足すと3回撮り直すことになる。

### 学び3: 「調べる地点」を家具の中に置くと、押し出しで自分が届かなくなる

会社1Fの階段で発覚。段差を8個の当たり判定ボックスで作り、その**内側**に「階段で上がる」地点を置いたため、
毎フレームの押し出しでプレイヤーが判定範囲の外へ飛ばされ、Eキーが永久に効かなかった。
同じ構造がベッド・棚・机にもあり、そちらは押し出し距離が判定半径より小さかったので**偶然動いていた**。
（ベッドは90度回転させたのに当たり判定のAABBを回していないバグも同時に見つかった）

→ 次回に使う条件: 当たり判定を持つ家具に対する調べる地点は、**家具の外周＋プレイヤー半径の外側**に置く。
「たまたま動く」配置を通さないため、全エリアの spot を自動で踏んで回るテストを先に書く。

### 学び4: ハーネスの「タップ」はDOMの先頭要素を叩く

`page.locator('button, [role="button"], canvas').first()` なので、`<canvas>` が body 先頭にあると
タイトル画面に覆われて必ず失敗する。タイトル画面を body の先頭へ移したら、
**「タップするとゲームが始まる」という一番意味のある経路が検査対象になった**。
→ 次回に使う条件: オーバーレイで始まるゲームは、最初のボタンをDOMの先頭に置く。

### 学び5: importmap 方式は audit.mjs が2項目を誤判定する

`死にファイル`（three.module.js が HTML から未参照）と `参照切れ`（bare specifier の `three`）が × になるが、
**公開済みの 268-final-brawl でも同じ×が出る**（実測で確認）。importmap を静的解析していないため。
→ `docs/audit-calibration.md` に追記済み。
