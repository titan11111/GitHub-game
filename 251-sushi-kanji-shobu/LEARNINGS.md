## 2026-09-22｜客を黒い塊から顔のある2人にした

### 何をしたか

改修前の客は、CSS 2行の黒い角丸だった。

```css
.head{ position:absolute; bottom:0; width:30px; height:22px;
       border-radius:15px 15px 0 0; background:#0A1826; z-index:1; }
.head.a{ left:16%; } .head.b{ right:16%; height:17px; }
```

注文は吹き出し（`#bubble`）だけが喋っていて、**客本体は無言のシルエット**。
「待たせている相手」が人に見えていなかった。

これをインラインSVG 2体（常連の親父／若い女性）に置き換え、10通りの表情を付けた。
外部画像・外部フォント・追加リクエストはゼロ（通信量 0.05MB のまま）。

### いちばん効いた判断：**感情の状態を新しく作らなかった**

最初に考えたのは「表情用のステートマシンを別に持つ」だったが、コードを読んで捨てた。
この作品には、感情の出どころが**すでに全部揃っていた**。

| すでにあった値 | そのまま顔になるもの |
|---|---|
| `G.cur.wait / PATIENCE`（客の待ち時間） | 平常 → そわそわ → いらいら |
| `spawnOrder()` | 顔を上げて注文する |
| `pickFuda()` の正誤分岐 | 喜ぶ／面食らう |
| `giftTo()`・CPUの取得 | 相手側を向く |
| `finishNigiri()` | 頬張る |
| `wait <= 0`（客が帰る） | 怒って去る |

なので表情系が追加したのは `mood = {name, hold}` の2値と、既存の分岐に
`setMood(...)` を1行ぶら下げただけ。**ゲームロジックは1行も変えていない。**
`hold` が切れたら待ち時間から顔を導き直すので、「出来事の顔」と「状況の顔」が
自動で切り替わる。

> 再利用条件: 既存ゲームに表情・リアクションを足すときは、まず
> **「感情の根拠になる値がすでに動いていないか」** を探す。
> 大抵は残り時間・コンボ・ミス判定として既に存在していて、新しい状態は要らない。

### 描き分けの技術メモ

- 眉4種・目4種・口6種を**重ねて置き**、`#guest[data-mood="…"]` の属性セレクタで
  出すものだけ `opacity:1`。DOMの差し替え・再生成ゼロ（既存の「押下表現はクラス付替えのみ」と同じ思想）
- 体（`.fig`）と首から上（`.head`）を別グループにして、身を乗り出す／のけぞる／
  そっぽを向くを分離。SVGの `transform-origin` は**ユーザー単位で直接指定**した
  （`transform-origin:50px 70px`）。SVG要素の `transform-box` 既定は `view-box` なので、
  これが一番素直に効く
- 2人が同時に同じ動きをすると人形に見える。呼吸・まばたきの周期をずらし、
  反応の `transition-delay` を 0.07秒ずらした

### やらかしと修正

1. **撮影スクリプトがゲーム本体に負けた**
   表情を1つずつ固定して撮ろうと外から `data-mood` を書き換えたが、毎フレーム走る
   `applyMood()` と、進行中の `spawnOrder()` / CPU の `setMood()` に上書きされ、
   「joy を指定したのに order が写る」状態になった。10枚中6枚が別の顔だった。
   → **撮影用の別経路を作らず**、`state.paused = true`（veilは出さない＝画面を覆わない）で
   進行だけ止め、ゲーム本体の `setMood()` をそのまま呼ぶ方式に変更。10/10一致。
   *教訓: 検証のために本体と別の経路を作ると、検証していたのは別物になる。*

2. **客Aの口が口ひげと同化して「垂れたもの」に見えた**
   `order` / `oops` の開いた口が口ひげの直下に来て、暗い色同士がくっついていた。
   スクリーンショットを見るまで気付かなかった。→ 口ひげを2px上げ、口を下げて真円寄りに。

3. **WebKitが入っていなかった**
   `_tools/game-harness.mjs` は chromium を使うので気付かないが、iPhoneが主戦場なので
   表情の確認は WebKit で撮りたかった。`ms-playwright` に webkit-2287 しか無く、
   playwright 1.62 は webkit-2336 を要求して起動失敗。`npx playwright install webkit` で解決。

# 2026-09-22（3）対戦相手の選択と、エンディングの称号

## 依頼

オープニングの次にCPUを選べるようにする（見習い寿司職人／寿司職人／ベテラン寿司職人）。
ベテランが現在のCPU相当。下2人はスピードを落とし、見習いはたまに間違える。
エンディングに「君は〜だ」形式の評価を入れる。

## いちばん効いた判断：段位からCPUの強さを剥がした

着手前に `RANKS` を読んで、**段位が2つの役割を兼任している**ことに気づいた。

| 段位が持っていたもの | 内容 |
|---|---|
| `take[]` | 品書きの構成（特上の枚数）＝プレイヤー側の難度 |
| `errMul` / `reactAdd` / `skip` | CPUの強さ＝相手側の難度 |

ここに「相手を選ぶ」を足すと、**強さの決定要因が段位と選択の2系統になり、どちらが効いたのか
誰にも説明できなくなる**。一人前の `errMul:1.5`（＝CPUをわざと弱くする補正）とベテランの選択が
同時に掛かると、「やさしい相手を選んだのに勝てない／むずかしいはずが勝てる」が起きる。

そこで段位は**品書きの構成と昇格だけ**を持たせ、強さは新設の `CPUS` に一本化した。
ベテランは旧 `hanaita`（`errMul:0.7 / reactAdd:0`）をそのまま引き継いでいるので、
「現在のCPU＝ベテラン」という依頼の言葉と実装が一致する。

**一般化**: 難易度選択を後から足すとき、既存の進行度パラメータが強さも兼ねていないか先に見る。
兼ねていたら、足す前に剥がす。剥がさずに足すと二重適用になる。

## 数字を勘で置かず、シミュレーションで引いた

称号のしきい値を「だいたい30貫くらいで…」と置きかけて止めた。
`index.html` の定数とループを写した90秒シミュレータを書き、2,000席×3プレイヤー模型で回した。

| プレイヤー | 見習い | 職人 | ベテラン |
|---|---|---|---|
| 初心者 | 勝率65% / 44貫 | 28% / 43貫 | 4% / 41貫 |
| 中級 | 99% / 59貫 | 83% / 58貫 | 38% / 56貫 |
| 上級 | 100% / 78貫 | 100% / 76貫 | 95% / 74貫 |

ここで**想定していなかった事実**が出た。**プレイヤーの得点は相手の強さにほとんど動かない**
（初心者は誰と当たっても41〜44貫）。理由は、手が塞がる時間と客の待ち時間で1席あたりの
注文総数がほぼ決まり、相手が弱いと「相手の取り分」が減るだけでこちらの処理能力は変わらないから。

この発見で称号の設計が決まった。**得点は相手に汚染されていないので、そのまま腕の物差しに使える。**
勝敗ではなく貫数を基準にし、しきい値は分布の p10/p50/p90 から引いた。

## 弱い相手を狩れないようにした一手

得点が相手に依存しないなら、見習い相手に78貫出せば最上位称号が取れてしまう。
そこで**相手ごとに称号の上限**を付けた（見習い→「うまい」まで／職人→「客を幸せにする」まで）。
最上位だけは貫数に加えて「ベテランに勝つ」を条件にした。
上限に当たったときだけ「この腕は、見習いでは測りきれない。」と出す。
**強い相手を選ぶ理由をここで作っている。**

## 見習いの誤答に上限を付けた理由

`TIER.err × errMul` をそのまま使うと、見習い（×2.0）の特上が **84%** 誤答になった。
CPUのお手つきは**その注文をプレイヤーに進呈する**仕様なので、これは
「たまに間違える相手」ではなく「特上を自動で献上してくる相手」になる。
`errMax:0.42` で頭を抑えて、並10% / 上30% / 特上42% に落とした。

**一般化**: 誤答率を倍率で調整するとき、いちばん誤答率の高い段で上限に当たる。倍率だけでは足りない。

## harness は PASS したが、それは何も保証していない

`_tools/game-harness.sh` は PASS（8項）。だがこれは**起動・描画・サイズ**の機械チェックで、
「相手を選べるか」「称号が正しく出るか」は1つも見ていない。今日の別件で同じ罠を踏んでいる。

そこで変更専用の検証スクリプトを書いて実測した（`verify251.mjs` / **25項すべてPASS**）。

## 2026-09-22 公開前に見つけた「半分だけ入った改修」

公開指示を受けて未コミット差分（+25/-8）を検査したところ、**開始画面のHTMLだけが入って
CSSとテキストが入っていなかった**。実際に WebKit 390px で撮って確認した症状:

- `<h2 id="mainTitle">` が**空**。タイトル「寿司漢字勝負」が画面に1文字も出ていない
  （`aria-label` にしか文字がなく、読み上げ以外には存在しない状態）
- `.kawa` `.yuge` `.noren` `.titlewrap` `.seal` `.gold` は **参照1回ずつ＝CSS定義ゼロ**。

`prefers-reduced-motion:reduce` で のれん・湯気・文字送りを止める分岐も入れた。
