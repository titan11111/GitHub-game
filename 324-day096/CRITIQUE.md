# 324 批評（4段ゲート 第1段）

作成: 2026-10-17 ／ 入力: `RESEARCH-taiko.md`、参考写真（大太鼓・両面打ち・暗転舞台）

## 1. この企画の核は何か

調査で一番強かった事実はこれです。

> 腕に力が残っていると、バチが皮に触れている時間が長くなり、響きが死ぬ。熟練者は当たる直前に力を抜く。（脱力技能の定量化研究）

**これはそのままタッチ操作に変換できます。**

- 指を**短く離す**（タップ）＝ 脱力できた ＝ よく響く「ドーン」
- 指を**押したままにする** ＝ 力が残った ＝ 皮にバチが残って詰まった「ドッ」

リズムゲームはたくさんありますが、多くは「いつ押すか」しか見ていません。
**「どう離すか」で音色が変わる太鼓**は、調査から直接出てきた、このゲームだけの手触りです。
この1点を企画の中心に置きます。3D・光・質感は、この手触りを気持ちよく見せるための脇役です。

## 2. 良いところ（伸ばす）

| # | 点 | 理由 |
|---|---|---|
| 1 | 「離し方＝音色」の操作 | 調査の一次情報に根拠がある。指導者の5段階評価（フォーム→大きな音→脱力→しなやかさ）がそのまま上達の段階になる |
| 2 | 絵になる題材 | 黒背景と1灯のスポットは、モデルが少なくても成立する。iPhoneで重くなりにくい |
| 3 | 音を合成できる | サンプル音源なしで20MB鉄則に余裕で収まる。強弱でピッチの下がり方が変わる、というサンプルにはできない表現ができる |
| 4 | 両面打ちの2人 | 手前（自分）と奥（相方）で、奥行きと掛け合いが自然に生まれる |
| 5 | 仕事への転用 | 「力を抜くと結果が良くなる」は研修の比喩として強い（力みの自覚、脱力の体験）。R&Dとしての筋がある |

## 3. 危ないところ（先に潰す）

| # | リスク | 起きること | 対策（SPECに反映済み） |
|---|---|---|---|
| R1 | **iOSの音の遅延** | Web Audio の出力遅延（実機で数十ms）のせいで、判定が「合っているのにズレる」 | 判定は `AudioContext.currentTime` 基準にする。設定に**タイミング補正（±100ms）**と、自動で測るキャリブレーションを置く |
| R2 | **3Dの人体が不自然** | 手続き生成のリグは、関節が棒のように動いて「躍動感」と逆の印象になる | 人体は**ローポリの塊（法被のシルエット）**に割り切る。見せるのは**腕・バチ・腰のひねり**の3つだけ。顔は暗くして描き込まない（写真も輪郭だけが光っている） |
| R3 | **「押したまま」と「長押しの操作」が衝突する** | ため打ち（大きく振りかぶる）を長押しに割り当てると、脱力の判定と矛盾する | **ため＝上へのスワイプ**、脱力判定＝**タッチ時間**。長押しを操作に使わない |
| R4 | **作り込みの範囲が広がる** | 光・質感・人・音・譜面を全部やろうとして、どれも中途半端になる | MVPは**曲1つ・太鼓1台・奏者2人**。演目の追加は第2段階 |
| R5 | **低音がiPhoneのスピーカーで聞こえない** | 60〜90Hzの基音はスピーカーでほぼ鳴らない | 体で感じる低音とは別に、**170〜230Hzの「芯」**（調査の実測値）と**アタックノイズ**で、小さいスピーカーでも打感を出す。イヤホンでは低音が足される |
| R6 | **バイブとの同期** | iOS Safari は `navigator.vibrate` 非対応 | 振動に頼らない。画面の揺れ・皮の凹み・光の閃きで打感を出す |
| R7 | **写真の人物の再現** | 参考写真は実在の演奏の写真 | 構図と光だけを参考にする。衣装は一般的な法被の意匠にし、特定の団体・人物に似せない |
| R8 | **操作の弱さ** | 左右の親指のタップだけでは単調になる | 縁打ち「カッ」（太鼓の縁付近のタップ）と、ため打ち（スワイプ）を足して3種類にする。口唱歌の「ドン・ドコ・カッ」と対応させる |

## 6. 批評の結論

**進めてよい。** ただし条件が3つあります。

1. 「離し方＝音色」を最初の1曲で必ず体験できること（チュートリアルで明示する）
2. R1（音の遅延）の補正を、ゲームロジックより先にコントロールパネルに入れること
3. 人体はシルエットに割り切り、バチの軌跡と光に描画の予算を使うこと
