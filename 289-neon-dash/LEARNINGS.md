# LEARNINGS — 289｜LUNAR STRIKER（月面機動ロボ）

- 日付: 2026-10-03
- 位置づけ: `robot-action.html`（SVGロボのモーション試験）を土台に、横スクロール宇宙アクションへ作り替え。旧「NEON DASH 99」を置き換えた（フォルダ番号・名前は不変）

## 何をしたか

- ロボの関節アニメ・入力・残像は土台のまま継承。ステージを「canvas(背景・敵) ＋ SVG(ロボ) ＋ canvas(弾・爆発)」の3枚重ねに組み替えた
- 背景は ①星空 ②月 ③岩の大地 の3枚＋足場。すべて起動時にオフスクリーンcanvasへ1回だけ手続き描画し、毎フレームは `drawImage` のみ（画像ファイル0本・0.06MB）
- 敵4種＋ボス、HP制、スコア、ポーズ、ミュート、`tg.289.best` / `tg.289.mute`
- 土台にあった Google Fonts の外部読み込みは index.html では外した（外部CDN依存0件）

## 効いた判断

- **岩は「輪郭線」ではなく「岩塊の重ね」で作る**。高さ配列から稜線を引くと山並みにはなるがゴツゴツしない。1塊ごとに「明るい面／暗い面／稜線の縁光／亀裂」を持つ多角形を作り、高い順に奥から重ねると岩に見える
- **月の迫力は半径と欠け際**。画面高400に対し半径120。クレーターは縁に近いほど扁平にし（球面の見かけ）、最後に欠け際の暗いグラデーションを被せると球になる
- **重い描画は1回だけ**。前回の改修で速度低下が未解決だったため、グラデーションや加算合成はすべて事前描画側へ寄せた。実行時の加算合成は光球スプライトの `drawImage` に限定
- 視差の基準を `camX` と別の `bgX`（累積値）にした。リトライで `camX` を0へ戻しても背景が飛ばない

## 検証（証跡）

- `_tools/game-harness.sh 289-neon-dash` → **RESULT PASS**（描画ループ 61 RAF/秒／コンソールエラー0／リクエスト失敗0／0.06MB）
- ブラウザ実行（デスクトップ幅・自動操作12秒）: 毎秒フレーム数 60〜62、`window.onerror` 0件
- 実画面で確認したもの: タイトル／走行／ショット／2段ジャンプ／ダッシュ残像／ドローン／結晶スパイク／隕石と警告／ボス出現・HPバー・撃破／被弾でゲームオーバー表示／ポーズ中に座標が動かないこと／縦375×812でのレイアウト（横はみ出しなし）
- `_tools/audit.mjs`: ○23 ×3。×の内訳は ①同名function重複（`index.html` と `robot-action.html` の2ファイルを数えているため）②外部CDN依存（`robot-action.html` 側の Google Fonts。index.html は0件）③未コミット

## 未検証・正直に残すこと

- **iPhone実機では未確認**。60fpsはデスクトップのブラウザでの値。canvas 1280×800 を2枚＋SVGを重ねているので、実機の速度は `/game-local-test` で見る必要がある

- 横持ち（高さ520px以下）で左右にボタンを振り分けるレイアウトは未確認

## 2026-10-03 追記：コントローラ整理とロボ3機

### 何をしたか

- 画面下のUIを操作卓1枚に整理：十字キー（なぞれる円盤）／A・B／中央に SELECT・START／割り当て表示窓。ヘッダーのポーズボタンと説明文は撤去
- ジャンプを十字キーの上へ移し、A/B を機体ごとの攻撃に充てた
- SELECT でロボ切替。B＝赤の格闘型（6種の打撃＋ムーンサルト）、C＝金の多武装型（ホーミング／2連弾／ギャラクシー砲）
- iOS設定を `ios-game-base` / `game-touch-ux` のチェックリストに合わせた（touchend 300ms、contextmenu、全ボタン pointerdown、押下の沈み込み、vibrate）
- 起点ファイル `ios-base.html` はコピーしていない。土台が既にあったため、チェックリスト項目を既存ファイルへ足した

### 効いた判断

- **格闘型を入れるなら敵の側も変える**。ボスは画面右端に張り付くので殴れない。5〜7秒ごとに自機の前へ降りてくる動きを足した
- **機体の色替えは CSS変数の上書きだけ**（`#robot.tB{--s-a1:…}`）。拳・肩当て・背部ポッドは同じSVG内に置いて `display` で出し分け。関節アニメは3機共通
- 十字キーは閾値ではなく角度で判定（上下左右60度／斜め30度）。右へ走るつもりで指が少し上にずれてもジャンプが暴発しにくい

### 検証（証跡）

- `_tools/game-harness.sh 289-neon-dash` → RESULT PASS（61 RAF/秒・エラー0・0.08MB）
- 実画面で確認：操作卓の見た目（375×812とデスクトップ幅）／ロボBのパンチ・キック・ムーンサルト（撃破まで）／ロボCのホーミング・2連弾・ギャラクシー砲（ウォーカー撃破）／ウォーカー単体の見た目
- スクリプトで確認：START で title→play→pause→再開、SELECT で 0→1→2→0、十字キーの右・右上・下・離す でクラス付替えと移動・停止、ムーンサルトが「ため1秒→離す→約0.8秒飛行→着地」で進むこと

### 未検証・正直に残すこと

- **iPhone実機は今回も未確認**。十字キーの判定角度・ボタンの大きさ（A/B 64px、SELECT/START 56×44px）が親指に合うかは実機でしか分からない
- **振動（vibrate）は iOS Safari では動かない**（非対応）。Androidでのみ効く
- ロボBのジャンプパンチ／ジャンプキック／しゃがみパンチ／しゃがみキックは、コードは通っているが画面での見た目は未確認（確認したのは立ちパンチ・立ちキックのみ）
- ボスの突進と、ロボB・Cでのボス戦は未確認。3機の強さのバランスも未調整
- 横持ちレイアウト、音、`localStorage` 保存は前回と同じく未確認
- 検証中、スクリーンショット取得のたびに自動ポーズやキー解除が起きた（`visibilitychange` / `blur` が飛ぶため）。ゲーム側の不具合ではないが、実機でアプリ切替から戻ったときの挙動は見ておく必要がある

## 2026-10-03 追記：ステージクリア型へ拡張（敵・ボス追加／ロボの成長）

### 何をしたか

- エンドレス → **全3面＋周回**。面ごとにボス（ガンシップ／クラブ・タンク／要塞コア）、撃破で強化3択
- 新しい敵3種：シールダー（正面の弾を弾く）、ホッパー（飛びかかる）、砲台（迫撃弾）
- 成長2系統：その場の「パワーチップ」（Lv1〜3、被弾で減る）と、面クリアの「強化3択」（周回中ずっと残る）
- ロボAにも Bため技「ブーストラッシュ」を追加し、3機とも「Bため＝特殊技」に揃えた
- 面の見た目は色替えのみ（青の氷原／赤の要塞宙域）。新しい背景は描いていない

### 効いた判断

- 当たり判定の分岐を種類名の列挙からフラグ（`tg`＝弾の標的／`item`＝拾う物／`ng`＝攻撃が素通り）へ変えた。敵を足すたびに条件式を全部書き換えずに済む

## 2026-10-03 追記：ファンネル／ボス戦の導入演出と足場

### 何をしたか

- ロボCにファンネル（Lv1〜2は2基、Lv3は3基）。ホーミング弾の発射元を腕からファンネルへ変更。ため中・ギャラクシー砲中は銃口の周りに集合
- ボス戦：スクロール停止 → WARNING＋上下の黒帯 → ボスが右から約3.4秒で進入 → BATTLE START。進入中のボスは無敵で攻撃しない
- ボス戦中だけ浮遊足場を2つ（高さ80と150）。下からすり抜けて乗り、上で下を押すと降りる

### 効いた判断

- 足場の高さは「今のジャンプで届くか」を式で確認してから決めた。最初の配置（高い足場が横に68px離れ高さ158）は、低い足場の中央から1回のジャンプでは届かないことがテストで判明し、横の隙間34px・高さ150へ寄せた
- 足場の上ではしゃがみを無効にして「下＝降りる」に割り当てた。十字キーに余りが無く、ボタンを増やさずに降りる操作を作るため
- ブラウザ枠は描画が止まる（1回の操作で1フレームしか進まない）状態になったので、検証をハーネスと同じ Playwright のスクリプトへ切り替えた。枠のスクリーンショットは自動ポーズも誘発するため、動きの確認には向かない

### 検証（証跡）

- `_tools/game-harness.sh` → RESULT PASS（61 RAF/秒・エラー0）
- Playwright シナリオ（エラー0件）：ロボCのホーミングがファンネルから出る／ボス出現後 camX の変化 0／進入中 → BATTLE START／低い足場に着地（y=260・plat=true）／低い足場から高い足場へ1回のジャンプで着地／下で降りる／右端で止まる（x=622）／ため中と発射中のファンネル集合／ボス撃破で足場0個
- 画像で確認：ファンネルの見た目、黒帯、BATTLE START、足場の見た目、ギャラクシー砲
