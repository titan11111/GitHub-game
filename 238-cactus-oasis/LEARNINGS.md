- Three.js r170 は CDN せず `three.module.min.js` を同梱した。公開実体 0.73MB。import maps は iOS Safari でも動く。
- ハーネスのタップは `button, canvas` の DOM 先頭を取る。canvas を先に置くと Three.js の毎フレーム描画で「unstable」になり timeout する。開始ボタンを canvas より前に置く。

- 未検証: iPhone 実機の熱と FPS。WebGPU は使っていない。

## 2026-09-17 ラクダの横歩き修正＋サイズ1.5倍

- **横歩きの根因はモデルの前方軸のズレ**。`makeCamel()` は頭・首を +X に置いて作ったのに、更新側は `rotation.y = Math.atan2(vx, vz)`（＝ローカル +Z を進行方向に向ける式）を使っていた。90°ずれて常にカニ歩きになる。
- 直し方は2択（回転式に `-Math.PI/2` を足す／モデルを +Z 向きで組み直す）。**モデル側を +Z 向きに組み直した**。理由は脚アニメーションも同時に治るから: 脚は `rotation.x`（＝ローカル Z 方向に振る）で歩かせていたので、+X 向きモデルでは脚が横に振れていた。回転式だけ直すと胴体は治って脚は横振りのまま残る。
- 教訓: **3Dの向きバグは「表示の回転」だけ見ると半分しか直らない**。モデルの前方軸を決めて、回転式・脚/腕の振り軸・当たり判定の3つを同じ軸に揃える。
- サイズは `config.js` に `CAMEL_SCALE` / `CACTUS_SCALE` を新設して 1.5 倍。マジックナンバーを `makeCamel()` と `applyCactusStage()` に直書きしない。
- **未調整（意図的）**: 食害判定 `near.d < 0.95`、進路妨害 `toP < 1.15` などのゲーム定数は触っていない。見た目が 1.5 倍になった分、ラクダとサボテン／園丁の重なりは以前より大きく見える。バランスを変えたくなったらここを触る。
- 証跡: harness PASS（RAF 61/秒・コンソールエラー0・0.70MB）、Playwright スクショでラクダが進行方向へ頭を向けて歩くこと・サボテンが大きくなったことを目視確認。
