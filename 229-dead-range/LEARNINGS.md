## 2. 「緩和策が切れると罰に変わる」構造がリズムを生む

呼吸ゲージの設計を分析して抽出した、**他ジャンルへ転用できる型**。

```
プレイヤーに強力な緩和策を与える（息止め＝手ブレ88%減）
 → ただし有限（2.4秒で枯渇）
 → 枯渇時は素の状態より悪化する（息切れ2.3倍）
```

これだけで「使う→戻す→また使う」の周期が**ルールを書かずに**生まれる。
スタミナ・オーバーヒート・集中力など名前を変えれば STG・アクション・格闘へそのまま載る。

**改修で分かった実装上の急所は3つ。**

### 2-1. 瞬間切替にしない

```js
// 悪い: 息を止めた瞬間にブレがカクッと消える
const amp = base * (canHold ? .12 : 1);
// 良い: 0.35秒かけて銃が「落ち着いていく」
S.holdQ += ((canHold ? 1 : 0) - S.holdQ) * Math.min(1, dt * (canHold ? 4.6 : 6.5));
const amp = base * (1 - S.holdQ*.88);
```
補間を挟むだけで、同じ数値なのに「銃を落ち着かせている」感触が出る。

### 2-2. 罰は溜まるのを速く、抜けるのを遅く

旧実装は `breath < .05` の間だけ1.9倍という**閾値の点滅**だった。0.05を超えた瞬間に
罰が消えるため、息切れの重さが残らない。連続量 `gasp`（増1.5 / 減0.42）に変えて、
使い切った代償が数秒尾を引くようにした。

### 2-3. 内部状態は「見える」まで存在しないのと同じ

本作の手ブレは**照準ではなく世界を動かす**ため、プレイヤーは自分が何をしているか
目で確認できなかった。連動の可視化を4つ足して初めてメカニクスが伝わった。

1. 銃が同じ `amp` で揺れる（息を止めると銃身が静まる）
2. 安定度バー `1 - amp/58`
3. 心音の間隔が残量に連動（`.30 + breath*.42` 秒）
4. ラベルの三段変化「呼吸／息を止めている／息切れ」

**一番効いたのは1**。数値のフィードバックより、握っている物が静かになるほうが速く伝わる。

## 3. 速度の「潮」は恐怖を作る。ただし非対称にすること

一定速度で近づく敵は的でしかない。速度を2層で変調したら緊張感が跳ねた。

- **層1（群れ）**: 静寂×0.52 → 進行×1.00 → 突進×1.85
- **層2（個体）**: 一体ずつ独立タイマーで不意に踏み込む

**急所は補間の非対称性**。

```js
S.tideMul += (target - S.tideMul) * Math.min(1, dt * (target > S.tideMul ? 5.5 : 2.6));
```

加速5.5・減速2.6。対称にすると「速度が変わっている」だけで恐怖にならない。
**急に来るのが怖く、緩むのはじわっとしていい**。

遷移確率も偏らせる。突進の後は58%で静寂、静寂の後は66%で突進。ランダムを
そのまま使うと波にならず、ただのノイズになる。

## 4. 「リアルにする」＝ディテールを足すことではない

ゾンビ描画の改稿で、最初に足したディテール（ぼろ布・血痕・指）はほとんど効かず、
**効いたのは骨格の比率と明度**だった。

| 試したこと | 結果 |
|---|---|
| 頭を `.088h` → `.072h` | ◎ 「大頭のマスコット」から人間の比率へ |
| 腰を `-.46h` → `-.50h`、脚を左右 `±.13w` → `±.21w` へ開く | ◎ 一本の柱に見えていたのが二本脚になった |
| 前腕だけ素肌の色にする | ◎ 手が浮いて見える問題が消えた（服と同色だと腕が背景に溶け、手だけ球になる） |
| 腕を横に垂らす → 体の前へ回り込ませる | ◎ 「立っている」から「掴みかかる」へ |
| 明度を1段落とす | ◎ 夜の画に戻った。**明るい緑の塊は暗い背景で浮いてホラーにならない** |
| ぼろ布・血痕・指 | △ 近距離でしか効かない。無くても成立する |
| 接近警告の赤い楕円 | ✕ **撤去**。UIの落書きに見えて没入を壊した。眼の発光を強める形に置換 |

**教訓**: シルエットが人体に見えていない段階でテクスチャを足しても無駄。
比率 → 明度 → 動き → 装飾 の順に直す。

### 描画と当たり判定を幾何学的に一致させる

頭の大きさを変えると、`fire()` のヘッドショット判定 `top + h*.21` とズレる。
**頭の中心を `shY - hr*1.0` に固定し、全種別で同じ高さにした**ことで、判定式を
触らずに描画だけ差し替えられた。姿勢差（猫背・前傾）は肩の球と胴の輪郭で表現する。

- 走行体の前傾を「頭を下げる」で表現しようとすると、頭が判定帯の外に出て
  **速い敵ほどヘッドショットしにくい**という理不尽が発生する。実際に一度踏んだ

## 8. 一人称の銃は「絵の向き」ではなく「投影の向き」で決まる

初版の銃は**真横から見た側面図**を右下に貼っていた。ドット絵としては整っていたが、
正面から来るゾンビに対して銃口が画面の外を向いて見えた。

原因は塗りでも角度でもなく、**世界と銃で投影方式が違っていた**こと。世界は
`x = W/2 + (z.x - camX) * f / z.d` という透視で描いているのに、銃だけが平面図だった。
「銃を回転させる」「傾ける」ではこの矛盾は消えない。**同じ `f/z` に乗せる**しかない。

### やったこと

銃をローカル3D（`X=右 / Y=下 / Z=銃口方向`）で組み、断面ごとに `f/z` で縮めた。
部品は「奥へ伸びる箱」`gbox(u0,u1, x0,x1, y0,y1, 上面色, 側面色)` の1関数だけで済む。

```
gp(u, x, y)  // u:0=銃床 1=銃口 → 画面座標と、その地点の縮尺 s を返す
```

### 効いた3点

1. **軸の収束先＝照準**にした。`gp(u)` は `u→∞` で `(GX, GY)` に収束するので、
   `GX,GY` を画面中央に置くだけで「銃身の延長線が必ず照準を通る」が保証される。
   目分量で角度を合わせる作業が消えた
2. **見える面だけ描く**。視点は銃の左上後方なので、描くのは左側面と上面の2枚だけ。
   上面を明るく・側面を暗くしただけで立体になった。最初は全部同じ色で塗っていて、
   形は正しいのに**闇に溶けて何も見えなかった**
3. **反動・マズルフラッシュが自動で正しくなった**。反動はZを手前へ引くだけで
   「銃が近づく＝大きくなる」が出る。フラッシュは銃口の投影座標に置き、半径を
   その地点の縮尺に比例させると、奥で光るので小さく鋭くなる。
   側面図時代は画面左端に巨大な火の玉が出ていた

### つまずいた点：据え位置をローカル座標で持つと縦画面で破綻する

最初は「銃床は右へ124、下へ98」とローカル座標で持っていた。横長では正しく見えたが、
**iPhone縦（390×780）では銃が画面右外へ完全に出た**。ローカルのずれは縮尺 `s` を
掛けて画面へ出るので、画面幅と無関係に大きくなるため。

据え位置を**画面比率**（`nx:.30, ny:.36` ＝ 中心から右へ30%・下へ36%）で持ち、
その地点の縮尺で割ってローカル値へ戻す形に変えた。縦持ちは別値（`tnx:.40` 他）。
これで横長・縦長とも同じ構図になる。

> **教訓**: 透視投影に載せた要素は、画面のどこに出るかを直接指定できない。
> 「画面のここに置きたい」を先に決めて、投影の逆算でローカル値を出す。

## 9. 「3体に1体」は乱数で書くと 3体に1体にならない

蛇行する反転種を「3体に1体」で出す指示に対し、最初 `Math.random() < 1/3` を考えた。
期待値は 1/3 だが、実際には5体連続で出ないことも3体連続で出ることもある。
プレイヤーが体感するのは期待値ではなく**目の前の並び**なので、これは仕様違反になる。

通し番号 `S.spawnN++` を持ち、`S.spawnN % 3 === 0` で判定した。比率が必ず 1/3 になる。

- 検証は目視ではなく実測にした。3秒×30サンプルで各個体の x を追跡し、
  **反転種の振れ幅 291〜347 / 通常種 6〜29** を確認してから完了とした
- 色の反転は `255 - 各チャンネル` の素直な実装。歩行体 `#3f5638` → `#c0a9c7` で、
  緑一色の群れの中に淡紫が1体だけ浮く。**別の色を選ぶより、反転のほうが必ず目立つ**

## 10. 効果音は「耳で確かめる」しかないと思い込んでいた

Web Audio で作った音は、Playwright では聞けない。だから今まで「たぶん鳴っている」で
済ませていた。**OfflineAudioContext で書き出して波形を測れば、機械で検証できる。**

```js
const ctx = new OfflineAudioContext(2, 44100*3, 44100);
AC = ctx; MASTER = null; REV = null; ECHO = null;   // バスを新しい文脈で作り直す
shot();
const buf = await ctx.startRendering();   // ← PCM が手に入る
```

ここからピーク・RMS・鳴っている長さ・左右のエネルギー比・ゼロ交差率を出す。
**無音（`()=>{}`）を対照に必ず1本入れる**。これが 0 になることで、測定系そのものが
正しいと言い切れる。

### この測定で実際に見つかった3件

1. **銃声のピークが 0.898**。単体では割れないが、唸りや薬莢と重なると 1.0 を超える。
   耳では気づけない領域だった
2. **`DynamicsCompressor` は薬にならなかった**。リミッター代わりに挿したら
   ピーク 0.898 → **0.205**。-13dB も持っていかれ音全体が痩せた。
   threshold を -9 → -3 に緩めても 0.281 までしか戻らない。**外して master を .72 に
   下げるほうが正しかった**。実測がなければ「リミッターを入れたので安全」で終わっていた
3. **金属音が 0.03 秒で切れていた**。ノイズの減衰指数 3.4 が急すぎて、
   「カチッ」ではなく「ツ」になっていた。1.5 に緩めて解決

> **教訓**: 音は主観だと思って検証を諦めていたが、**ピーク・RMS・帯域は数字で出る**。
> 「良い音か」は測れなくても、「割れるか」「短すぎないか」「距離差が出ているか」は測れる。

## 11. ゾンビの声は「低音のブーン」では群れにならない

改修前の唸りは鋸波1本をローパスに通しただけで、**全個体が同じ音量・同じ位置**で鳴っていた。
30体いても「1つの機械音」にしか聞こえない。

### フォルマント合成に変えた

母音は「共鳴する3つの帯域」で決まる。声帯（鋸波）＋かすれ（ノイズ）を
**バンドパス3本**（例: あ＝560/830/2400Hz）に通すと、ブーンではなく「うぅ／おぉ」になる。
基本周波数・母音・ビブラート速度を毎回振ると、同じ声が2回鳴らない。

### だが効果が大きかったのは合成より「個体化」だった

`groan()` を `groan(z)` に変え、ゾンビの実体を渡すようにしただけで印象が変わった。

| 変えたもの | 実測 |
|---|---|
| 距離で音量 | 近 RMS 0.0057 / 遠 0.0009 ＝ **6.3倍差** |
| 距離で高域（ローパス） | 近 806Hz / 遠 510Hz（ゼロ交差） |
| 横位置で定位 | 左 **135:1** / 右 **1:33** |

姿が見えない距離でも「右奥に2体、左手前に1体」が音だけで分かる。
**音の質を上げるより、音に位置を持たせるほうが恐怖に効いた。**

## 12. 「N体に1体」を2種類同時に置くと、片方が必ず削れる

肥大体を「7体に1体」、反転種を「3体に1体」で入れた。どちらも通し番号の剰余で
比率を保証していたが、**21体目が両方に当たる**。肥大体を優先した結果、
反転種は 1/3 のはずが **2/7（0.286）** に痩せていた。70体で実測して初めて気づいた。

借り（`S.invDebt`）を持たせて、衝突で落ちた反転種を次の非肥大体へ繰り越す形にした。

```js
if(fat && inv){ S.invDebt++; inv = false; }
else if(!fat && !inv && S.invDebt > 0){ inv = true; S.invDebt--; }
```

210体で 肥大体30（＝1/7）・反転種69（＝1/3 − 端数1）。両方成立する。

> **教訓**: 剰余で比率を保証する仕組みは、2本以上並べた瞬間に保証が壊れる。
> 並べたら必ず**まとめて実測**する。片方だけ数えても気づけない。

## 13. 「急に来る敵」は、来る前に必ず予告する

肥大体は巡航 14.2 → 猛ダッシュ 99.6（実測）。倍率は約7倍で、走行体の巡航58も超える。
これをそのまま出すと理不尽になる。突進の前に **0.50秒の溜め**を必ず挟んだ。

- **速度で予告**: 溜め中は 3.2 まで落ちる。「止まった＝来る」が体で分かる
- **形で予告**: 体が沈み込む（`scale(1.07, 0.88)`）
- **色で予告**: 足元の赤い輪が広がる。**音を切っていても分かる**
- **音で予告**: 36Hz → 98Hz へせり上がる唸り。解放の瞬間に号砲＋振動70ms

予告を4系統に重ねたのは、iPhoneで音を切って遊ぶ人が多いため。
**恐怖は「避けられたはずだ」と思えるときにだけ成立する。**

## 2026-09-10 | 背景を3枚重ねに作り直した（夜空・雲・廃墟）

### やったこと
背景を **オフスクリーンcanvas 3枚を焼いて視差差で重ねる** 構造へ置き換えた。画像ファイルは1枚も追加していない（アセット0のまま・フォルダ384KB）。

| 層 | 内容 | 視差 |
|---|---|---|
| far | 夜空グラデ／天の川（帯＋粒900＋暗黒星雲）／星約380（周縁減光・色温度差・明星に十字光条）／月／地平の緑がかった靄 | .025 |
| mid | ちぎれ雲3帯。月に向いた側だけ銀の縁光。常時ドリフト＋巻き戻し | .09＋流れ |
| near | 廃墟スカイライン2列（崩れた天端・露出鉄筋・生き残った窓）＋枯れ木7本（再帰枝5段） | .21 |

月は「円＋ずらした暗円」の三日月をやめ、**位相の幾何**で描き直した: 本体の周縁減光グラデ → 海（マリア8個・回転と縦潰しで不規則化）→ クレーター40個（暗い底＋光の当たる縁）→ ティコの光条 → 半円＋楕円の合成パスで欠け際 → 地球照 → 暗い側のリムライト。

焼けない要素（星の瞬き30個・月暈の呼吸・地平の靄の揺れ）だけを毎フレーム live で足している。

### 学び

1. **「画像を重ねたい」＝画像ファイルを足すこととは限らない**。このゲームは全描画がCanvasなので、オフスクリーンcanvasを3枚焼けば要求どおり「画像3枚重ね」になり、20MB鉄則にも一切触れない。素材を増やす前に「何を画像と呼んでいるか」を確認する。

2. **層のアンカーは「地平線を下端に置く」で統一すると事故らない**。horizonY() は camY とズームと反動で ±230px 動く。層ごとに y オフセットを個別計算すると必ずズレる。全層を「下端＝地平線」で焼き、`hz - 層の高さ` に描くだけにした。

3. **パディングの二重加算で月が画面外へ飛んだ**（実際に発生）。`my = h - (H*.26 + BG.pad)` と書いたが、pad はすでに層の高さ h に含まれていた。1枚目のスクショで月が消えていて発覚。**焼いた層は必ず目視で確認する**——ハーネスは PASS を返す（描画ループもエラー数も正常なので、消えた月は機械には見えない）。

4. **月の位相はずらした円ではなく半円＋楕円で描く**。ずらした円は「二つの球が重なった」影になり嘘っぽい。半円と楕円を合成したパスなら本物の明暗境界になる。境界は12段に分けて薄く重ねるとグラデーションになり、1回のfillのような硬い線が出ない。

5. **雲の縁光は「月の方向へオフセットした同じ形」で作れる**。明るい版を月方向へ ch*.42 ずらして先に描き、その上に暗い本体を重ねる。それだけで月に面した側だけが銀色に光る。

6. 不気味さは色ではなく**情報の少なさ**で出る。廃墟の窓を全部光らせると街になる。30%の建物に1〜2個だけ灯すと「まだ誰かいる」に変わる。

### 仕上げ（同日・出荷パイプライン）

出荷前の iOS 検査で2点の抜けを検出して塞いだ。**背景の作業とは無関係に前から抜けていた穴**で、パイプラインを通さなければ見つからなかった。

- `-webkit-touch-callout:none` / `-webkit-user-select:none` 未指定 → 仮想ボタンの長押しでiOSのコピーメニューが出る
- `.btn` に `touch-action` 未指定 → `touch-action:none` は html/body に効いていたが**継承されない**ため、ボタン上のダブルタップ拡大が生きていた
- ついでに `overscroll-behavior:none` と `-webkit-text-size-adjust:100%` を追加

**学び: `touch-action` は継承しない。** html/body に書いたから全体に効いている、は誤り。タップを受ける要素それぞれに要る。
