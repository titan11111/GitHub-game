# 木琴とネコ：音楽に応じた猫の行動拡張案

検討日: 2026-09-08
対象: mokkin-neko.html
状態: 2026-09-08 木琴の横並び・自動バチ・不機嫌/威嚇/ひっかき/噛みつきを本体へ実装。Chromiumのタップ・キー入力テストを通過。iOS実機・音の聴感は未検証。

実測: 高音の交互連打で満足度0、威嚇→ひっかき→噛みつきに到達。ゆっくりした低音演奏で満足度100。再挑戦時の状態初期化を確認。待機時の回復は50までに制限。下記は当初の設計案であり、あくび等の全項目を実装済みとするものではない。

## 実現性

実装可能。既存の木琴演奏を対象とする場合、外部AIや音楽解析サービスは不要。
音の高さ・間隔・並びを judge() が判定し、apply() がくつろぎ度を更新している。
drawCat() のCanvas描画に、行動ごとの姿勢・移動・口・前足の動きを追加できる。
曲ファイルやマイクからの音楽を対象にする場合は、音声入力・特徴抽出を別途設計する。

## 推奨する体験

猫は「現在の気分」と「一時的な行動」を別々に持つ。
同じ演奏でも、直前まで安心していたか、嫌な音が続いていたかで反応を変える。
これはゲーム内の猫の好みであり、実際の猫の反応を予測する仕様ではない。

| 演奏・状況 | 行動 | 見た目・音 |
| --- | --- | --- |
| 低い音をゆっくり鳴らす | 喜ぶ・甘える | 目を細める、体を揺らす、ゴロゴロ |
| 下りの音階・安心が続く | くつろぐ・眠る | 丸くなる、あくび、ゆっくり呼吸 |
| 大きく音が跳ぶ | 興味を持つ | 首をかしげる、耳を動かす |
| 高音が続く | 驚く・不機嫌 | 肩が跳ねる、耳を伏せる、尾を強く振る |
| 嫌な演奏が続く | 威嚇する | 背を丸め、口を開き「シャー」 |
| 威嚇後も連打が続く | ひっかく | 手前へ寄る、前足を振る、一瞬の爪跡 |
| 強い不機嫌が続き、攻撃の待ち時間も経過 | 噛みつく | 手前へ飛び出して口を開閉、「カプッ」、戻る |
| 演奏を止める・穏やかな音へ切り替える | 落ち着きを取り戻す | 警戒姿勢を解き、定位置へ戻る |

ひっかく・噛むは流血や負傷のないコミカルな演出とする。
操作を長時間妨げず、穏やかな演奏へ戻すと回復できる。
ランダムだけで攻撃せず、耳・しっぽ・威嚇による予告を出す。

## 実装構成

1. 状態 S に行動名、開始時刻、持続時間、攻撃待ち時間、連続した不快刺激の蓄積を追加。
2. apply() で気分更新後に行動を選択。進行中の攻撃は途中で毎打鍵上書きしない。
3. drawCat() に喜び・驚き・威嚇・ひっかき・噛みつき・睡眠の姿勢と補間を追加。
4. 爪跡や吹き出しは猫・木琴の描画後に重ね、画面サイズに合わせて配置。
5. 猫の鳴き声はWeb Audioで軽量な合成音を試作。自然さが不足する場合は利用権を確認した録音素材に交換。
6. 再挑戦では行動・待ち時間・音の間隔を初期化。終了時は気分に合う声を出す。

## 同時に直すべき既存箇所

- judge(): 異なる音を0.09秒未満で連打すると、rush より先に chord が成立する。短時間の入力群をまとめ、和音の加点頻度を制限する。
- judge(): 音階・同音判定に時間上限がない。古い入力を同じフレーズとして扱わない。
- loop(): 静けさによる回復がフレーム単位。経過秒で計算し、画面の更新頻度で回復速度が変わらないようにする。
- finish(): 不機嫌でも無条件に purr() が鳴る。結果に応じた発声へ切り替える。
- finish()/start(): 結果の文字送りタイマーを再挑戦時に解除し、前回の表示が混ざらないようにする。
- prefers-reduced-motion: 現状はCSSのtransitionのみ対象。Canvasの飛び出し・揺れも弱める。

## 実装後の確認条件

- ゆっくりした低音で喜び、安心が続くと眠る。
- 高音・連打で不機嫌になり、威嚇を経てひっかき・噛みつきがそれぞれ見られる。
- 交互の超高速連打で好感度を稼げない。
- 攻撃は毎打鍵で連発せず、演奏を止めると回復する。
- 再挑戦で前回の攻撃・文字・待ち時間が残らない。
- 不機嫌な終了でゴロゴロが鳴らない。
- スマートフォンのタップとPCのキー操作で反応が一致する。
- 動きを減らす設定では強い飛び出し・画面揺れを使わない。
- 音声の聴感と画面の見やすさを実機で確認する。

## 推奨する初回範囲

既存の木琴入力を使い、喜ぶ・首をかしげる・不機嫌・威嚇・ひっかく・噛む・眠るを追加する。
曲のアップロードやマイク入力、猫の性格選択は別段階とする。
完了の判断はコード追加だけでなく、各行動を実際の演奏操作で再現できることとする。
