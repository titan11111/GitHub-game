# 323 ひかりのしずく（ぷるぷる スライム だいぼうけん）SPEC

## これは何か
ヤミに奪われた「いずみの5つのひかり」を取り戻す、5ステージ構成の横スクロール アクション。
主人公はスライム1匹。倒すより「しみこむ・のっとる・わかれる」で切り抜ける設計。

- エントリ: `index.html`（単一HTML＋`audio/`＋`fc-ios-controller.css`）
- 画面: 256×224（SFC比 8:7）を上、ファミコン風コントローラを下に置く携帯機レイアウト
- 主戦場: iPhone Safari

## 合格条件（この仕様を満たさなければ未完成とみなす）

### 1. 通しプレイ
- タイトル →（はじめから）→ プロローグ5ページ → 1面 → … → 5面 → エンディング、が一本で繋がる
- ステージクリアで **スライム残機を持ち越し、+1UP（上限5）**。しずく・ひみつのほし・タイムは**通算**で加算する
- 5面クリアはクリア画面を出さず、そのままエンディングへ入る

### 2. タイトル画面
- ステージセレクトは**置かない**（通しプレイのみ）
- メニューは「はじめから」／「つづきから」の2択。セーブが無いときは「つづきから」を出さない
- 十字キー上下で選択、A/B/X/Y かタップで決定。画面のどこをタップしても決定が通る
- 全5面クリア済みなら `★ ALL CLEAR ★` を表示する

### 3. セーブ／コンティニュー
- `localStorage` キーは `tg.323.save` / `tg.323.cleared`（この接頭辞を変えない＝セーブが消える）
- セーブ内容は「到達ステージ・通算しずく・通算ほし・通算タイム」。**つづきから＝そのステージの最初から、残機3**
- ゲームオーバー時は「つづきから（同じステージのチェックポイントから・残機3）」と「はじめから（1面から・通算リセット）」を選べる

### 4. 音（場面に応じて切り替える）
| 場面 | 曲 |
|---|---|
| タイトル・プロローグ・エンディング | `audio/over-the-clover.m4a` |
| 1〜5面の通常プレイ | `audio/jump-before-you-land.m4a` |
| ボス戦 | 内蔵チップチューン `boss` |
| 死亡・クリア・ポーズ | 曲を止める（効果音のみ） |
- 曲は `fetch`→Blob で**丸ごと取得してから**再生する（ストリームを残さない／ループの継ぎ目が汚れない）
- 「おと」トグルで曲も効果音も同時に止まること

### 5. iOS 鉄則
- Pointer Events に統一し `setPointerCapture` を使う。ダブルタップ拡大・ラバーバンドを殺す
- 音声は最初のタップ（touchend/click/keydown）で unlock する
- バックグラウンド復帰で入力が張り付かない（`clearInputs()`）
- 公開実体は 20MB 以下（現状 2.84MB）

### 6. コントローラ（ファミコン風）
- 見た目は共通部品 `fc-ios-controller.css`（`titans-ui/src/components/Controls/`）を**参照**する。CSSの中身を index.html へコピペしない
- 構成: 上段にシステム列（かわる／おと／ふるえ／ポーズ＝SELECT・START相当）、下段に黒の十字キー／ターボ型 X・Y／丸ボタン A(赤)・B(黄)
- 灰色のシェルは画面下の余白いっぱいまで伸ばし、**デッキは常に画面の最下端に接する**（親指が届く位置に固定する）
- タッチの受けは据え置く: 十字キーは座標から方向を出し、A/B/X/Y は**一番近いボタンへ寄せる**（指が滑っても落とさない）

### 7. 操作レスポンス（触り心地の合格条件）
- 1フレーム（約16ms）だけのタップでもジャンプが成立すること（入力ラッチ）
- 十字キーは**ヒステリシス**を持つ: 押し始めは中心から11.5%、離れ判定は5.5%。親指が中心へ流れても入力が落ちない
- ポインタ移動のたびに `getBoundingClientRect()` を呼ばない（ボタン座標はレイアウト変化時のみ再測定）
- 方向が変わった瞬間以外は十字キーの `style.transform` を書かない
- 物理側の数値は据え置く: コヨーテ 8F／先行入力 9F／振り向き加速 1.9倍／A離しでジャンプ打ち切り／頂点のわずかな滞空

### 8. 5面「ほしのうちゅう」の見え方
- **遠景と近景を明確に分ける**。ぼかさず、明度・色・スケールで分ける
  - 遠景（星雲・惑星・星）には暗い veil（`#070c22` 34%）をかけて後ろへ下げる
  - 中景に**浮遊島のシルエット層**（視差0.12・窓の灯りつき）を入れる
  - 近景のブロックは明るく、彫りを強くする
- **ブロックはラピュタの浮遊ブロック**として描く: 左上に光る面取り、右下に影、目地（モルタル）で1個ずつ分かれて見えること
- 10個に1個はルーン入りブロックで、`(G.t>>4)` で明滅する
- 下に何も無いブロックの底面と、動く足場の底面には**浮遊の光**を出す
- 星はひとつずつ周期・下限・振れ幅・色温度を変える（一斉点滅にしない）

## 「凍る」ギミックの設計案（未承認・未実装）
スライムは水の体なので「凍る」が素直に効く。入れるなら次の形を提案する。

| 要素 | 案 |
|---|---|
| 入口 | 2面「ひかりの洞窟」の最奥に氷の区画を足す（既存5面は構成を崩さない） |
| 操作 | 冷気に触れている間に **X（ふわり）を押すと硬化** し、数秒 氷スライムになる |
| できること | ①水面・溶岩の上を**滑って渡る** ②上から落ちて**ひび割れブロックを割る** ③トゲを弾く |
| 失うもの | 硬化中は しみこむ・ぶんれつ・ぱくっ が使えない（硬いので吸収できない） |
| 解除 | 時間切れ、または熱源に触れる。解除時は水たまりに戻って しずく を1つ落とす |
| 既存との噛み合い | 「柔らかいから入り込める」の裏返しとして「硬いから壊せる・滑れる」を置く＝今の設計思想と対になる |

着手するなら、2面の氷区画のレベルデザインから（タイタンの承認待ち）。
