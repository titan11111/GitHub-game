## 2. ハードの制約を自分に課す（GB様式の文法）

実機 DMG の制約を**再現ではなく遵守**する。

| 項目 | 実機 DMG | 本作の実装 |
|---|---|---|
| 解像度 | 160×144 | canvas を 160×144 固定。CSS で**整数倍のみ**拡大 |
| 色 | 4階調モノクロ（緑LCD） | `#0f380f` `#306230` `#8bac0f` `#9bbc0f` の4色のみ。**第5の色を使わない** |
| スプライト | 8×8 / 8×16、3色＋透明 | 16×16 は 8×8 タイル4枚相当として扱う。透明1＋3色 |
| BG層 | 1層のみ（パララックス不可） | **多重スクロールを使わない**。奥行きはディザ帯とウィンドウ層で出す |
| ウィンドウ層 | BG の上に固定の矩形（HUD用） | 画面下の「メッセージ枠」「ステータス枠」はウィンドウ層相当として常に整数位置に固定 |
| 音源 | pulse1(sweep)/pulse2/wave/noise | WebAudio: square×2＋custom periodic wave＋noise buffer の4ch |
| フォント | 8×8 タイル | 自作8×8ビットマップフォント（カタカナ46＋濁半濁23＋小書き4＋英数記号） |

### やらないこと（偽レトロ禁止）
- `arc()` `beginPath()` による曲線・斜め線 → **全部ドットで打つ**
- 小数座標の描画 → 全描画を `|0` スナップ
- スプライトの拡大縮小描画 → 等倍のみ
- システムフォントによる文字描画 → 一切使わない
- 半透明・グラデーション・影 → 4階調とディザのみで表現

## 3. 遊びの芯

### 3-1. ループ

```
駄菓子屋の自販機に ￥100 入れる
   ↓
レバーを回す → カードが1枚落ちる（★1〜★4）
   ↓
図鑑が埋まる／手札が増える
   ↓
カードを3枚選んで となりのコとバトル
   ↓
勝つと ￥100 ＋ カード1枚   負けても手札は減らない
   ↓
稼いだ金でまた回す → 図鑑16種コンプでエンディング
```

### 3-2. バトル（ここが本作の発明）

3ラウンド **2本先取**。各ラウンドの頭に「**おだい**」が1つ提示される。

| おだい | 比べる値 | 勝つのは |
|---|---|---|
| チカラ | kcal | **高い**方 |
| キンニク | たんぱく質 P | **高い**方 |
| アブラ | 脂質 F | **高い**方 |
| アマサ | 炭水化物 C | **高い**方 |
| **ヘルシー** | kcal | **低い**方 ← 逆転おだい |

- 手札3枚は**1ラウンドに1枚ずつ消費**し、使い回せない
- おだいは**そのラウンドが始まってから**開示される。「カレーライスをどこで切るか」が読み合いになる
- **ヘルシーの存在により最強札が存在しない**。カレーライス（700kcal）はチカラ・アブラ・アマサで無敵だが、ヘルシーでは**最弱**になる。サラダ（45kcal）に出番が生まれる
- 同値は引き分け（双方0本）

> **設計判断**: 選択肢のプレビューに出した「こうげき／まもる」コマンドは採用しない。
> ステータス比較に攻防コマンドを足しても選択の意味が薄く（どちらを選んでも数値は変わらない）、
> 「どのおだいにどのカードを当てるか」という**すでに存在する意思決定**を薄めるだけだと判断した。
> 意思決定は「おだい × 手札の配分」に一本化する。

### 3-3. 相手（CPU）
- 図鑑の獲得枚数に応じて手札の質が上がる（序盤は★1中心、終盤は★3〜4混在）
- 思考: おだいに対して**手札の中で最も有利な札**を出す。ただし 25% の確率で2番手を出す（完全読みにしない）

## 6. 操作（iOS主戦場）

DMG-01 の筐体を HTML/CSS で再現し、**実機と同じ配置の物理ボタン**を画面下に置く。

| 入力 | 役割 |
|---|---|
| 十字キー | カーソル移動 |
| A | 決定 |
| B | もどる |
| START | ポーズ／決定（タイトル） |
| SELECT | オト ON/OFF（ミュートトグル） |
| キーボード | 矢印／Z=A／X=B／Enter=START |

### 実装規約（CLAUDE.md「🎛 コントロールパネル」準拠）
1. **ミュートトグル必須** → SELECT ボタン＋ポーズ画面の両方から
2. **localStorage キーは `tg.232.*`** → `tg.232.save`
3. **Pointer Events に統一し `setPointerCapture` を必ず入れる**（押しっぱなしバグ防止）
4. iOS CSS: `body{touch-action:manipulation}` / `canvas{touch-action:none}` の2段構え
5. **明示ポーズ**（START）を実装
