## 1. いちばん効いた判断：「フレームバッファを1枚かませる」

GB様式を**気合いではなく構造で強制**した。

```js
const fb = new Uint8Array(160 * 144);   // 中身は 0..3 のパレット番号だけ
function px(x, y, c){ x = x|0; y = y|0; ... fb[y*160+x] = c; }
```

canvas2D の描画APIを**一切呼ばない**。`fillRect` すら使わず、全部この `fb` に書いてから
1回だけ `putImageData` する。この構造にした瞬間、`docs/retro-style-guide.md` の10条のうち
4条が**違反したくてもできなく**なった。

| 鉄則 | どう不可能になったか |
|---|---|
| ①ベクター描画禁止 | `arc` `beginPath` を呼ぶ口が無い（grep実測0件） |
| ②整数座標のみ | `px()` の入口で `\|0` する以外に書き込む経路が無い |
| ③ピクセル密度の統一 | スプライトは `fb` へ1:1で書く。拡大引数が存在しない |
| ⑤パレット規律 | 配列が0..3しか持てない。第5の色は物理的に置けない |

**教訓**: 181-crow-run が10条中7条を破ったのは、注意不足ではなく**破れる構造だったから**。
様式はチェックリストで守るより、**破れないAPIを1枚挟む**ほうが確実に守れる。
（2026-09-09 の Obsidianテンプレート強制フックと同じ発想。注意喚起 → 機械的強制）

## 2. フォントは「生成 → 目で見て → 直す」を回さないと事故る

カタカナ8×8を**手打ちで書き下ろすのは無理**だと早い段階で判断し、Playwrightで
システムフォントを8×8へ焼いて1bit化 → SVGアトラスにしてPNGで**実際に目視**した。

### そこで見つかった、目で見ないと絶対に気づかない不具合

| # | 症状 | 原因 | 直し方 |
|---|---|---|---|
| 1 | ガ ギ グ… が全部 カ キ ク に見える | 8×8に濁点の置き場が無く、閾値で消えていた | 本体を1行下げて rows1-7 に収め、row0 の (4,0)(6,0) に点2つ。半濁点は (5,0) に1つ |
| 2 | **ウ と ワ が1ビットも違わない同一グリフだった** | ウ の上の点が上辺の横棒に吸収された | ウ だけ手で打ち直し（上に点＋ワを1行下げる） |
| 3 | 小書き ッ ャ ュ ョ が大書きと同じ大きさ | サイズ指定をしていなかった | 描画ボックスを左下1/2に限定して焼き直し |
| 4 | 英数の G Q R I が崩れ、太さも不揃い | グリフごとに別フォントが選ばれていた | **英数記号45字は手打ちの5×7に差し替え**（カナだけ生成に任せる） |

**②が最重要**。「ラウンド1」が「ラワンド1」、「オオイホウ」が「オオイホワ」と出ていた。
自動生成の出力を**1枚の絵にして見る工程を挟まなければ、そのまま出荷していた**。

> 横展開できる型: **生成したアセットは必ず一覧画像に焼いて目視する**。
> 生成物の検証を「エラーが出ないこと」で代用しない。エラーは出ない。間違った絵が出るだけ。

同じ工程でスプライト16枚も回し、**banana / tamago / karaage / ice / natto / cake の6枚が
「何の絵か分からない」と判定**して描き直した（karaage はアヒル、banana は チェックマークに見えた）。
1周目で通したら、図鑑が意味不明な16マスになっていた。

## 3. 見つけた実バグ：速いタップが丸ごと消える

Playwright の `keyboard.press`（押して即離す）で**反応しない**ことに気づいた。

```js
// 修正前: フレーム間に down→up が収まると hold が 0→1→0 になり、pollInput が押下を一度も観測できない
if(hold[k] === 0) hold[k] = 1;
```

60fps = 16.7ms。iPhoneの素早いタップは**普通に16ms未満で終わる**ので、これは
テスト環境だけの話ではなく実機で取りこぼす。押下を latch に残して次フレームで必ず
消費する形へ変更した。

```js
if(hold[k] === 0){ hold[k] = 1; latch[k] = true; }   // 離されても latch は残る
```

**教訓**: `keydown` を「毎フレームの状態」だけで扱うと、1フレーム未満の入力は存在しないことになる。
`CLAUDE.md` のコントロールパネル規約③（`setPointerCapture` 必須）は押しっぱなし側の対策だが、
**逆方向（短すぎる押下）の穴は規約に無い**。ここは新しい知見。

## 4. ゲーム設計：最強札を作らないための「ヘルシー」

栄養データを**実データのまま**使うと、カレーライス(700kcal/P18/F25/C100)が
チカラ・アブラ・アマサの3お題すべてで無敵になり、ゲームが成立しない。

データを歪める（＝教材価値を捨てる）代わりに、**判定方向を反転するお題を1つ足した**。

- `ヘルシー` = kcal が**低い**ほうが勝ち

これだけで、カレーは「3つのお題で最強／1つのお題で最弱」になり、サラダ(45kcal)に
明確な出番が生まれた。5つのお題のうち1つが逆転枠なので、**手札3枚をどのお題に当てるか**が
毎回本物の読み合いになる。

> 型: **データを曲げずにルールを1つ足してバランスを取る**。
> 数字をいじると教材価値と説得力が同時に消える。ルール側なら両方残る。

| ツール | 結果 |
|---|---|
| `_tools/game-harness.mjs` | **PASS**（8項目全通過・0.05MB・RAF 61/秒・コンソールエラー0・リクエスト失敗0） |

直した×2件:
- `-webkit-touch-callout:none` が無かった → 追加
- ダブルタップズーム防止の touchend ガードが無かった → 追加（`touch-action` だけでは端末差が出る）

**直さなかった×1件（偽陽性）**: 「BGMループ設定 — ループ指定を検出できない」
本作のBGMは `<audio loop>` ではなく WebAudio の16分ステップシーケンサで、
`bgmStep % 32` で無限に回り続ける。ダミーの `loop = true` を足すのは
**採点を通すための細工**なので入れない。`docs/audit-calibration.md` に偽陽性として記録した。

## 7. 次に同じことをやるときの手順（再利用可能な型）

1. **批評を先に書く**。旧版の何が壊れているかを表にする（今回は「index.htmlが無い」「遊びが外部AI依存」が致命傷だった）
2. **遊びの芯が分岐するなら実装前に1問だけ聞く**。見た目を直してから中身が違うと分かるのが最悪
3. フレームバッファ層を先に作る（様式を構造で固定する）
4. **フォント・スプライトは生成 → アトラス画像 → 目視 → 直す**を必ず回す
5. Playwrightで1周（ガチャ→バトル→結果）を自動で通し、**未定義グリフとコンソールエラーを機械で0件確認**
6. harness → audit → 偽陽性は台帳へ → コミット
