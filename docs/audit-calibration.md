# 監査器キャリブレーション台帳

`_tools/audit.mjs` の**誤判定を記録して、監査器そのものを賢くしていく**ための台帳。
ここが「教育」の実体です。AIが賢くなるのではなく、**このファイルに書いた分だけ監査器のルールが太る**。

## なぜAIではなく台帳を育てるのか

AIに学習させると、何を学んだかが見えない。見えないものは検証できない。
監査器のコードとこの台帳に落とせば、**なぜその判定になるのかを後から誰でも読める**。
「教育」がテキストとして残る＝説明できる、という状態を優先する。

### 書き方のルール

- **「たぶん」「おそらく」は書かない。** 裏取りしたコマンドか行番号を残す
- 誤判定の種類は2つ。両方ともここに書く
  - **偽陽性（×なのに実は正しい）** — ループが正しいコードを壊す原因。最悪
  - **偽陰性（○なのに実は壊れてる）** — 実機で落ちる原因。harnessやSPEC側の穴かもしれない
- 直せなかったときは「直せない理由」を書く。空欄にしない

## 2. autofix 昇格カウンタ

自動修正を「全部か無か」で解禁しない。**項目ごとに実績で昇格させる**。

**昇格条件: 半自動で3回直して、3回とも再監査で○になったら `autofix: true`**
**降格条件: 誤判定ログに1件でも偽陽性が載ったら即 `false` に戻す**

| 項目 | 成功回数 | 状態 |
|---|---:|---|
| 読み込まれていないJS/CSSがない | 0/3 | 手動 |
| 重複コードがない（同名function重複定義） | 0/3 | 手動 |
| safe-area対応 | 0/3 | 手動 |
| BGM開始処理（ユーザージェスチャー内でunlock） | 0/3 | 手動 |
| 不要なデバッグ出力が残っていない | 0/3 | 手動 |

※ 人間箱の5項目（未使用アセット / 参照切れ / パス切れ / 外部CDN / SPEC.md）は**昇格対象外**。永久に人間が決める。

**現在の自動化率: 0/31項目**

## 3. 決定の履歴（監査器の憲法）

判定基準を変えたときは必ずここに残す。基準がいつのまにか緩むのを防ぐため。

| 日付 | 決めたこと | 理由 |
|---|---|---|
| 2026-08-02 | 根拠なしの ○ は実装レベルで × に自動降格 | 「根拠を書いて」と頼む方式は忖度で崩れる |
| 2026-08-02 | 判定は ○/×/― の3値。静的解析で測れない項目は ― | ×と混ぜると直せない項目で永久にFAILしてループが止まる |
| 2026-08-02 | **3MB鉄則を撤廃**。サイズは参考値として表示のみ | 3MB超でFAILにすると大半のゲームが成立しない（タイタン判断） |
| 2026-08-02 | 人間箱／機械箱の仕分けは `audit.mjs` に静的に書く。AIに仕分けさせない | 仕分けをAIに任せた瞬間に丸投げに戻る |
| 2026-08-02 | 「たぶん直った」でのコミット禁止。判定は exit code のみ | AIの自己申告を信じたのが過去の失敗の根因 |
| 2026-08-02 | 想定外の事態（誤判定・修正しても×が減らない）は**その場で停止して聞く**。事前に分かってる仕様判断は**最後にまとめて4件** | 前者は原因が新鮮なうちに台帳へ書きたい。後者は中断が無駄 |

## 4. Obsidian同期について

現状このファイルはリポジトリ内のローカルmd。Obsidianへは同期していない。
Obsidian / Notion のMCPは**認証が通っていない**ため、このセッションからは書き込めない。
（claude.aiのコネクタ設定、または対話セッションで `/mcp` から認証が必要）

同期するとしても、**正はこのリポジトリ内のファイル**にしたい。理由は `audit.mjs` のコードと同じコミットに乗るから。
「判定を変えた」と「台帳に書いた」がgit上で1つの変更として残るのが、あとから追える唯一の形。
