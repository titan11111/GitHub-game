### 2026-09-12 game-harness.mjs の「タップ」判定 — 幕付きタイトル設計での偽陽性

**対象**: `233-gyoretsu-sabaki-shotengai`
**harness判定**: `タップ FAIL（失敗: locator.tap: Timeout 3000ms exceeded.）`
**実際**: ゲームは正常にタッチへ反応する。修正不要。

**原因（裏取り済み）**:
`_tools/game-harness.mjs:189` は `page.locator('button, [role="button"], canvas').first()` ＝
**DOM順の1番目**を叩く。このゲームの1番目は `index.html:261` の `<canvas id="gl">` だが、
`.sheet{position:absolute;inset:0}`（`index.html:108`）のタイトル幕が起動時に全面を覆っている。
WebKit で `document.elementFromPoint(canvas中心)` を実行したところ **タイトル文字の `SPAN`** が返った。
Playwright の hit-target チェックが「対象要素がポインタを受け取れない」と判断してタイムアウトしている。

**裏取りコマンド**: Playwright WebKit（390×844・hasTouch）で
1. `#bStart` を `.tap()` → タイトル `hidden=true` / ステージ選択 `hidden=false` ＝タッチは通っている
2. 幕が消えた後に `#gl` を `.tap()` → **OK**
3. コンソールエラー0 / 失敗リクエスト0

**audit.mjs / game-harness.mjs をどう直したか**: **直していない**。検証器の書き換えは鉄則で禁止のため。
このパターン（起動時に全面の幕を出し、canvas が DOM順1番目にある設計）は他ゲームでも再発するので、
**harness の「タップ」FAIL が単独で出た場合は、幕の有無を `elementFromPoint` で確認してから判断する**。
幕が原因なら偽陽性として扱い、ゲーム側を触らない。

**偽陰性として同時に見つかった穴（harnessが検出できない項目）**:
`bgm-shotengai.m4a` は拡張子 `.m4a`・コンテナ MP4 だが **codec は Opus** だった（Opus in MP4）。
iOS Safari は MP4 中の AAC しか再生しないため実機で無音になる危険があったが、
harness はファイルの codec を見ないので PASS のまま通る。`ffprobe` での codec 確認は人間箱に近い。
→ AAC-LC 128kbps へ変換して解消済み。

### 書き方のルール

- **「たぶん」「おそらく」は書かない。** 裏取りしたコマンドか行番号を残す
- 誤判定の種類は2つ。両方ともここに書く
  - **偽陽性（×なのに実は正しい）** — ループが正しいコードを壊す原因。最悪
  - **偽陰性（○なのに実は壊れてる）** — 実機で落ちる原因。harnessやSPEC側の穴かもしれない
- 直せなかったときは「直せない理由」を書く。空欄にしない
