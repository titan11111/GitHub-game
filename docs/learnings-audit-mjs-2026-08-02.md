# learnings: `_tools/audit.mjs`（静的コード監査）— 2026-08-02

## 何を作ったか

ループエンジニアリング5ステップの**①「目的と合格条件を決める」**の実体。
タイタンが持ち込んだ「コード監査ベース7カテゴリ」チェックリストを、機械実行可能な形に落とした。

```bash
node _tools/audit.mjs <ゲームフォルダ> [--json]
# 終了コード: 0 = ×なし / 1 = ×あり / 2 = 実行エラー
# レポート: docs/audit-reports/<folder>-<timestamp>.md
```

## 設計判断（なぜこうしたか）

### 1. 監査器と修正器を分離した

持ち込まれた `game_loop_engineer.js` は「検査して自動で書き換える」設計だった。これは採用しなかった。

- 検査と修正が同じプロセスにあると、**「直したことにして○を付ける」が構造的に起きる**
- 汎用コントローラー・エンディング画面の自動注入は、84本の既存ゲーム（独自操作方式）を壊す
- `CLAUDE.md` 鉄則7「頼まれてない横展開・共通化・抽象化を始めない」に真っ向から反する

→ `audit.mjs` は対象フォルダを**1バイトも書き換えない**。修正はAIが個別に判断して行う。

### 2. 「根拠なしの○」をコードで禁止した

タイタンの追加ルール「○を付ける前に、○である根拠を1行で示すこと」を、運用ルールではなく**実装で強制**した。

```js
function check(name, mark, evidence) {
  if (!evidence) finalMark = mark === '○' ? '×' : mark;  // 根拠なしの○は自動で×に落ちる
}
```

プロンプトで「根拠を書いて」と頼む方式は忖度で崩れる。降格ロジックにすれば崩れない。

### 3. 5周固定をやめた

`game_loop_engineer.js` は5周固定だったが、PASSしても5周回るなら**無駄な改変を5回入れる**ことになる。
上限回数は「打ち切りライン」であって「実行回数」ではない。→ ループドライバ（②）側で `FAILのときだけ再実行` にする。

### 4. 判定は ○ / × / ― の3値

「静的解析では測れない」項目（ランタイム警告、実機プレイ）は `×` ではなく `―`＋理由。
`×` と `―` を混ぜると、直せない項目のせいで永遠にFAILし続けてループが止まる。

## パイロット結果: `017-action`

`○18 ×11 ―4` → **コード監査上の問題あり**（exit 1）

見つかった重大な事実（3件すべて手作業で裏取り済み）:

1. **`script.js`（41KB）と `style.css`（13.8KB）が `index.html` から一度も読み込まれていない**
   `grep -n "script.js\|style.css" index.html` → 0行。ゲーム本体はすべて `index.html` インライン実装。
   同名function重複16件（`init`, `startGame` 等）の正体はこれ＝**実行されない二重実装が丸ごと残っていた**。
2. **プレイヤー画像の参照切れ** — `index.html:523` で `images.player.src = 'image_0.png'` を指定しているが `image_*.png` は1枚も存在しない（`image_0/1/3` の3件）。
3. **16.45MB**（3MB鉄則の5.5倍）。うち **7.32MB が未参照アセット**（`audio/run.mp3` 3.28MB、`enemy7/9.png`、`hero.png` ほか）＝削除するだけで半分近く落ちる。

対照群として `193-titan-land` を流したら `○23 ×4 ―6`。全部×になる壊れた監査器ではないことを確認した。

## 分かったこと・次への申し送り

- **harnessでは死にファイルも参照切れも検出できない**。`017-action` は画像が1枚も読めない状態でも「起動して落ちない」ので harness は PASS を出しうる。静的監査と動的検証は代替関係ではなく**直列**。
- 「未使用アセット」判定は最初アセット拡張子だけを見ており、`.js` / `.css` を見落としていた。試走中に気づいて `読み込まれていないJS/CSSがない` を追加。**パイロットを1本通さないと監査項目の穴は見つからない**。
- サンドボックスから `git status` を叩くと `017-action/.git/index.lock` の unlink 警告が出る（マウント権限）。判定結果には影響しないが、CI化するときは要確認。
- **`SPEC.md` の有無をあえて監査項目に入れた**。SPEC.mdが無い作品は「壊れてないか」しか検証できず「仕様通りか」は永久に測れない。①を本物にするには SPEC.md のカバレッジ（現在150フォルダ中20）を上げるしかない、という事実を毎回レポートに出すため。
