## 1. 3機種のハード制約と、そこから生まれた美学

### ファミコン（1983）
- **画面**: 256×240。BG1層タイル（8×8）＋スプライト（8×8/8×16、1ラインに8枚まで→点滅）
- **色**: 全52色から、BG4パレット＋スプライト4パレット（各3色+透明）
- **音**: 矩形波2ch＋三角波1ch＋ノイズ1ch（＋DPCM）
- **生まれた美学**:
  - 少色ゆえの**強いシルエット**と**輪郭線**。キャラは「黒フチ＋明色2色」が基本形
  - 背景は**タイルの繰り返し**が見えるのが正しい（雲と茂みが同じ形＝マリオ）
  - BGMは「メロ（矩形1）＋ハモリ/裏メロ（矩形2）＋ベース（三角）＋ドラム（ノイズ）」の4声が完成形

### PCエンジン（1987）
- **画面**: 256×239中心。BG1層だがスプライトが大きく多い（16×16〜32×64）
- **色**: 512色中、最大482色同時（9色×16パレット×BG/SP）— 当時圧倒的な多色
- **音**: 波形メモリ音源6ch（＋CD-ROM²なら生音）
- **生まれた美学**:
  - **明るい・鮮やか・アニメ調**。キャラゲー的なポップさ（ボンバーマン、PC原人、桃鉄）
  - 多色を活かした**グラデーション空**・大きくよく動くキャラ
  - FC的な暗さとは対極。「華やか」がPCEらしさ

### メガドライブ（1988）
- **画面**: 320×224。**BG2層＋ウィンドウ**、ラインスクロール（1ラインごとに横ずらし＝多重パララックス・路面うねり）
- **色**: 512色中、4パレット×15色+透明＝**61色同時**。少ない！
- **音**: FM音源YM2612 6ch＋PSG 3ch＋ノイズ
- **生まれた美学**:
  - 61色しかないので**ディザリング（市松の網点）で中間色・グラデを擬似生成** — MDの画面を拡大すると網点だらけ。これがMDの「質感」
  - **ハイコントラスト・メタリック・ダーク**（ソニック、ベア・ナックル、サンダーフォース）
  - **2層以上の多重パララックス**が標準装備。走ると背景が3〜4速度でずれるのがMDの気持ちよさ
  - FM音源の**硬いベース＋スラップ＋金属的リード**。ベースラインが主役級に動く

**要点**: 「ダークで渋い」だけではMDにならない。**ディザ・多重パララックス・ハイコントラスト・動くベースライン**が揃って初めてMDの世界観になる。

## 2. 共通文法 — 偽レトロにならないための鉄則10条

実機のグラフィックは「タイルとスプライトをVRAMに置く」以外の描き方が**物理的に不可能**だった。この不可能性を自分に課すのが様式再現の本質。

1. **ベクター描画禁止**: `ctx.arc()` `beginPath()` の斜め線・円は即アウト（滑らかな輪郭は実機に存在しない）。円も月も爆発も全部ドットで打つ
2. **整数座標のみ**: 描画時は必ず `x|0, y|0` にスナップ。小数座標の fillRect はアンチエイリアスで縁がにじむ＝「なんかぼやけて変」の主犯
3. **ピクセル密度の統一**: 1論理ドット＝1canvasドット。スプライトだけ2倍拡大描画（drawImageのスケール）すると、背景と「ドットの大きさ」が食い違う＝実機ではありえない画
4. **画面拡大は整数倍のみ**: CSS拡大は floor した整数倍（×2,×3…）。端数倍だとドット幅が2pxと3pxで混在し、スクロールで波打つ
5. **パレット規律**: 色相ごとに明度3〜4段のランプを組む。**スプライトは輪郭色＋リムライト（明るい縁）で背景から必ず浮かせる** — 暗い背景に暗いキャラは実機ゲームでは絶対にやらない（CRTで見えないから）
6. **フォントはビットマップ**: システムフォント（Courier等）のアンチエイリアス文字は世界観を一発で壊す。8×8の自作ドットフォント、または画数の少ないカナ/英数に限定
7. **音は最低3声**: メロ＋ベース＋ドラム(ノイズ)。単音BGMは「様式」ではなくただの手抜きに聞こえる。FC=矩形波、PCE=柔らかい波形、MD=FMっぽい減衰の速い音＋動くベース
8. **アニメは3〜4フレーム＋強いシルエット**: 2フレームのパタパタは最低限。走り・羽ばたきは3〜4枚で「絵が流れる」。シルエットだけで何のキャラか分かる形に
9. **背景は2層以上のパララックス＋タイル繰り返し**: 遠景0.25×・中景0.5×・地面1.0×。地面はタイルパターンを流す（線1本は地面ではない）
10. **UI慣習を守る**: スコアは上部固定・等幅・ゼロ埋め（SCORE 003250）、点滅は8/16フレーム周期、ゲーム開始は「PRESS START」点滅。HUDに半透明やグラデは使わない

## 3. ケーススタディ: 181-crow-run はなぜ「変」だったか

2026-07-04の一撃生成（12KB・机上ゲート全通過・自己評価85点）が実機で「作りが変」と評価された。診断結果＝**上記10条のうち7条に違反**:

| # | 違反 | 該当コード |
|---|------|-----------|
| 1 | 月が `ctx.arc` の滑らかな円、トゲが `beginPath` の斜め線 | drawBG/drawObs |
| 2 | プレイヤーY・障害物Xが小数のまま描画（縁がにじむ） | update/draw全般 |
| 3 | カラス16×12を32×24に拡大描画 → 背景(1×)とドット密度不一致。タイトルでは×3でさらに混在 | drawPlayer |
| 4 | fit()が端数倍スケール → ドット幅が不均一、スキャンラインとモアレ | fit() |
| 5 | ほぼ黒のカラス(#101018)を、ほぼ黒の空(#07070f)＋暗いビルの上に描画 → **主役が見えない**。明度ランプなし、輪郭・リムライトなし | PAL定義 |
| 6 | Courier New＋日本語システムフォント（AA付き）でタイトル・HUD | text() |
| 7 | BGMが三角波の単音16ステップのみ（ベース・ドラムなし） | BGM配列 |

**教訓**: 検証4点セット（構文・配信・実プレイ）は「動くこと」のゲートであって「世界観」のゲートではなかった。**様式チェックリスト（下記）を出力前ゲートに追加する。**

## 4. 実装パターン（次回から一撃生成テンプレに組み込む）

```js
// ① 整数スナップ描画（全描画をこれ経由に）
const px = (v) => v | 0;
ctx.drawImage(img, px(x), px(y));            // 等倍のみ。スケール引数を渡さない

// ② 整数倍フィット
function fit(){
  const s = Math.max(1, Math.floor(Math.min(innerWidth/W, innerHeight/H)));
  wrap.style.width = W*s+'px'; wrap.style.height = H*s+'px';
}

// ③ パレットランプ（例: MD夜景）— 色相ごとに暗→明3段＋リム
// 空:#0a0a14 遠景:#1c1c30 中景:#30304e / 主役:輪郭#000 本体#3a3a55 リム#8f95c0 目#ffd75e

// ④ ディザ（MDの質感）: 2色の市松でグラデ帯を作る
for(let y=0;y<8;y++)for(let x=0;x<W;x++) if((x+y)&1) ctx.fillRect(x,skyY+y,1,1);

// ⑤ 3声シーケンサ（メロ+ベース+ノイズドラム、16分×150ms）
// メロ: 矩形波配列 / ベース: 三角波でルート-5度往復 / ドラム: 偶数拍にノイズ短発
```

- 解像度の推奨: FC風=256×240、MD風=320×224。16:9が必要なら**320×180のままでいいが上記10条を厳守**（解像度より文法違反の方が致命的）
- 8×8ビットマップフォント: 数字+英大文字だけ自作すればHUDは足りる。日本語はタイトル画像（ドット打ち）にする

## 5. 出力前チェックリスト（レトロ様式ゲート）

- [ ] arc/beginPathによる曲線・斜め線がゼロ（全部ドット）
- [ ] 全描画が整数座標（`|0` スナップ）
- [ ] スプライト拡大縮小描画なし（等倍のみ・密度統一）
- [ ] 画面フィットが整数倍
- [ ] 主役スプライトが背景から浮いている（輪郭＋リムライト。縮小スクショで一目で見つかるか）
- [ ] システムフォント不使用（ビットマップフォント or ドット絵タイトル）
- [ ] BGM3声以上（メロ＋ベース＋ドラム）
- [ ] 主要アニメ3フレーム以上
- [ ] パララックス2層以上＋地面タイル
- [ ] （MD風のみ）ディザによるグラデ表現が1箇所以上ある
