# コントロールパネル実装ポイント5選

> 対象: `~/GitHub-game` のゲーム内 **操作/設定UI**（タッチ操作・仮想パッド・音声・一時停止・設定保存）
> 抽出方法: 264ゲームフォルダを横断grepし、パターン別に「該当ゲーム数」で頻度を測定
> 抽出日: 2026-09-12

---

## ① iOS前提のCSSヘッダー5行が、事実上の共通規格になっている

最新10本（`289-neon-dash` 〜 `298-star-shooter`）は、冒頭のCSSが **1バイト違わず同一**。

```css
-webkit-user-select:none; user-select:none; -webkit-touch-callout:none;
touch-action:manipulation; -webkit-tap-highlight-color:transparent;
padding: env(safe-area-inset-top) env(safe-area-inset-right)
         env(safe-area-inset-bottom) env(safe-area-inset-left);
/* canvasだけは別扱い */
canvas{ display:block; width:100%; height:100%; touch-action:none; }
```

- `touch-action` 使用 **177/264本** ／ `safe-area-inset` **140本** ／ 選択・長押し抑止 **174本**
- **ポイント**: `body` は `manipulation`（ダブルタップズームだけ殺す）、`canvas` は `none`（スクロールも殺す）の**2段構え**
- ⚠️ **課題**: 共通CSSファイルになっておらず、毎回コピペで持ち回っている。この完全一致は「テンプレ化の成功」ではなく「手コピーが10本続いた」状態

## ② 入力バインドが2世代混在している（Pointer Events へ寄せるべき）

| 世代 | 実装 | 該当数 |
|---|---|---|
| 旧 | `touchstart` + `mousedown` 二重バインド | touchstart系 139本 |
| 新 | Pointer Events 単一バインド | pointerdown 115本／`setPointerCapture` 61本 |

```js
// 旧（288-mossroot）: 同じ挙動に6本もバインドが必要
el.addEventListener('touchstart',on,{passive:false});
el.addEventListener('touchend',off,{passive:false});
el.addEventListener('touchcancel',off,{passive:false});
el.addEventListener('mousedown',on);
el.addEventListener('mouseup',off);
el.addEventListener('mouseleave',off);

// 新（278-elevator-chanbara）: 3本＋キャプチャで、指がボタン枠外へ離れても取りこぼさない
el.setPointerCapture(e.pointerId);
el.addEventListener('pointerdown',on);
el.addEventListener('pointerup',off);
el.addEventListener('pointercancel',off);
```

- **ポイント**: `setPointerCapture` の有無が「押しっぱなし判定のバグ」の分岐点。**61本しか入っていない**
- `{passive:false}` の明示は **151本** に浸透済み（ここは優秀）

## ③ 仮想パッドは「CSS相対サイズ＋押下クラス」のDOMオーバーレイ型（70本）

canvas内に描かず、**DOM側にオーバーレイ**するのが定石になっている。

```css
.dpad{ position:relative; width:min(42vw,148px); height:min(42vw,148px); flex-shrink:0; }
.dpad .arr{ position:absolute; pointer-events:none; opacity:.7; }   /* 矢印は当たり判定を持たせない */
.dpad.press-u .arr.u{ opacity:1; color:var(--kin); }                /* 押下フィードバックはクラス付替え */
.dpad-nub{ position:absolute; left:50%; top:50%; width:26%; height:26%; border-radius:50%; }
@media (max-height:600px){ .dpad{ width:120px; height:120px } }     /* 横持ち/小画面のフォールバック */
```

- **ポイント3つ**
  1. サイズは `min(42vw, 148px)` — 画面比と絶対上限の**両取り**。px固定だとiPhone SEで潰れる
  2. 矢印に `pointer-events:none` — 子要素が親のタップを奪わない
  3. 押下表現は**クラス付替えのみ**（再描画コストゼロ）
- `aria-label="十字キー"` を付けている実装あり（`278-elevator-chanbara`）。読み上げ配慮として横展開候補
- 方向ボタンを個別DOMで置く旧型は **31本** 残存

## ④ 音声unlockは定型化済みだが、ミュートUIが追いついていない

```js
function audioInit(){
  if(AC) return;
  try{ var A = window.AudioContext || window.webkitAudioContext;
       if(!A) return; AC = new A();
       mg = AC.createGain(); mg.gain.value = 0.22; mg.connect(AC.destination);
  }catch(e){ AC = null; }                    // 失敗してもゲームは動く
}
function unlock(){
  audioInit();
  if(AC && AC.state === 'suspended'){ AC.resume(); }   // iOSは必ずここを通す
  bgmStart();
}
```

| 項目 | 該当数 |
|---|---|
| WebAudio 使用 | 167本 |
| `AudioContext.resume()` | 137本 |
| unlock関数として切り出し | 73本 |
| 音量/ミュートの語が存在 | 123本 |
| **ミュート状態を実際に管理** | **76本** |

- **ポイント**: `try/catch` で囲んで `AC=null` に落とす＝**音が出なくてもゲームは止めない**設計。`mg.gain.value=0.22` のマスターゲイン固定も全作共通
- ⚠️ **課題**: 音量の語は123本あるのに状態管理は76本。**約47本は「音は鳴るが消せない」**可能性。iPhone主戦場でこれは致命的。ミュートトグルは最優先で共通化すべき

## ⑤ 一時停止は「自動」が主流、「明示ポーズ」は激レア（67本 vs 13本）＋設定保存キーが総崩れ

| 実装 | 該当数 |
|---|---|
| `visibilitychange`（バックグラウンドで自動停止） | **67本** |
| プレイヤーが自分で止められる明示ポーズ状態 | **13本** |
| `localStorage` 使用 | 110本 |

- **ポイント**: 「裏に回ったら止める」は入っているが、**プレイヤー主導で止める手段がほぼ無い**。電車プレイ前提なのに中断できないのは体験上の穴
- ⚠️ **設定保存キーの命名が4流派で混在**

```
rpgSavedState / rpgWaitingForReturn      … camelCase・接頭辞あり
coping-bgm-volume / bouzu-muted          … kebab-case・接頭辞あり
parachute_highscore / sakurazawa_streak  … snake_case
bestTime / wrongQuestionIds              … 接頭辞なし（衝突リスク）
```

- **設定パネルを共通化するなら、命名規約（例 `<folderNo>.<key>`）を決めるのが先**。接頭辞なしキーは同一オリジン（GitHub Pages）で**他ゲームと衝突する**
